# Проверки

Проверки — обычные скрипты в `tools/`: `python tools/test_<имя>.py` или `node tools/test_<имя>.mjs`,
код возврата 0 — пройдено. Сети, настоящих принтеров и рабочей папки данных наборы не трогают:
рабочие данные подменяются временными, сервер поднимается в изолированном режиме
(`app/e2e_isolation.py`: своя папка, порт и замок).

## Что запускать

```bash
python tools/validation/select_profile.py --working-tree
```

Селектор по изменённым файлам и карте рисков (`tools/validation/risk_map.json`) выводит список
наборов. Прогоните его **целиком** — выбор «на глаз» уже пропускал красное.

Быстрые проверки после любой правки: синтаксис (`python -m py_compile`, `node --check`), баланс
скобок в `web/app.css`, теги `web/index.html`.

## Каталог наборов

`tools/validation/test_catalog.json` — производный файл с хешами наборов. Изменили набор —
перестройте каталог, иначе исполнитель профилей откажется запускать проверки:

```bash
python tools/validation/build_test_catalog.py --write
```

## Интерфейс

`tools/_fm_ui_stage.py` — стенд: настоящие `web/index.html`, `app.js`, `app.css` и Vue, ответы
`/api` выдуманные. Изменения интерфейса проверяются на четырёх размерах окна (1600×1000,
1280×800, 1024×640, 853×533) и без ошибок в консоли.

## В открытом репозитории

Часть наборов закрытого репозитория сюда не входит: они сверяются с коммитами прежней закрытой
истории (доказывают, что изменение было намеренным относительно конкретного коммита), проверяют
устройство закрытого репозитория или настоящие обложки принтеров. Они остаются в закрытом
репозитории разработки. Наборы, которым нужен отсутствующий здесь модуль или файл, печатают
`SKIP` с причиной.

`tools/test_camera_fmp4.py` разбирает настоящий поток от ffmpeg, а ffmpeg в репозиторий не входит.
Положите `ffmpeg.exe` рядом с `server.py` или сделайте `ffmpeg` доступным в `PATH`. Без него набор
красный намеренно: разбор потока без настоящих байтов не доказан.
