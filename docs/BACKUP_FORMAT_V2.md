# Формат резервной копии конфигурации `.3diwell-backup` — версия 2

**Статус: ЗАМОРОЖЕН после выпуска Alpha 2.828. Постоянный публичный контракт.**
Расширение то же — `.3diwell-backup`. Версия контейнера различается по полю
`container_format_version` в `header.json`, а НЕ по расширению или содержимому payload.

- **v1 ([BACKUP_FORMAT_V1.md](BACKUP_FORMAT_V1.md)) НЕ изменяется** и читается навсегда.
- **v2 — новый основной контейнер для новых экспортов.** Меняет только упаковку и режим защиты;
  ЛОГИЧЕСКАЯ модель payload та же (тот же `serializer`, тот же `payload_schema_version`).
Правила совместимости — [BACKUP_COMPATIBILITY_CONTRACT.md](BACKUP_COMPATIBILITY_CONTRACT.md).

## Зачем v2

Обязательный пароль v1 избыточен для локального сценария владельца. v2 делает создание копии
**без пароля** основным простым режимом, а защиту паролем — дополнительной опцией. Формат v1
(всегда зашифрованный) остаётся полностью совместимым.

## Внешний контейнер (`container_format_version = 2`)

ZIP ровно с двумя записями и фиксированными именами:

| запись        | содержимое                                                        |
|---------------|-------------------------------------------------------------------|
| `header.json` | НЕсекретные метаданные + режим защиты (+ параметры шифрования для password) |
| `payload.bin` | канонический JSON (mode=none) ИЛИ ciphertext (mode=password)       |

Строгий разбор (`app/config_backup/container_v2.py`, переиспользует безопасные примитивы v1):
ровно две записи, строгие имена, никаких лишних/повторных записей, path traversal, symlink,
вложенных архивов, ZIP-с-паролем; те же лимиты размера и анти-bomb, что у v1. Данные из копии
**никогда не исполняются**.

### `header.json` (несекретный, оба режима)

```json
{
  "format_id": "com.3diwell.farm-manager.configuration-backup",
  "container_format_version": 2,
  "backup_id": "<случайный несекретный id>",
  "created_at": "2026-07-24 12:00:00 UTC",
  "created_by_app": "3DIWELL Farm Manager Alpha 2.828",
  "payload_schema_version": 1,
  "sections": ["core", "printers", "modules"],
  "printer_count": 3,
  "module_count": 0,
  "protection_mode": "none",
  "payload_encoding": "canonical-json-utf8",
  "payload_length": 1234,
  "payload_sha256": "<hex, по ОТКРЫТОМУ payload>",
  "required_reader_capabilities": ["cleartext-json-v2"]
}
```

Для `password_aes256gcm` дополнительно:

```json
  "required_reader_capabilities": ["aes256gcm-scrypt-v1"],
  "encryption": {"kdf": "scrypt", "n": 32768, "r": 8, "p": 1,
                 "salt": "<b64>", "cipher": "AES-256-GCM", "nonce": "<b64>"}
```

`header.json` (в ОБОИХ режимах) **не содержит** пользовательских данных: имён/IP/credentials
принтеров и значений настроек в нём нет. `payload_length`/`payload_sha256` считаются по ОТКРЫТОМУ
каноническому payload (в password-режиме привязаны через AAD).

## Режимы защиты

### `none` (по умолчанию, без пароля)

- `payload.bin` — канонический UTF-8 JSON логической модели (открытый текст внутри ZIP).
- **Пароль не запрашивается.** Пустой пароль как способ создать AES-ключ **запрещён**.
- `payload_sha256` и ZIP CRC защищают от **случайного** повреждения — но **НЕ** от намеренной
  подмены (открытый текст может изменить кто угодно, пересчитав SHA).
- Importer **обязан заново** выполнить полную schema/value/security-валидацию (данные из копии —
  данные, не команды; не доверяем заявленному).
- **Предупреждение пользователю (постоянно видимое в UI):** копия без пароля содержит настройки
  подключения принтеров, файл нужно хранить в защищённом месте.

### `password_aes256gcm` (дополнительно)

- `payload.bin` — ciphertext. Тот же проверенный стек, что v1: scrypt (n=2^15, r=8, p=1) → AES-256-GCM,
  случайные salt/nonce, **AAD = канонические байты header** (GCM даёт аутентифицированную целостность).
- Пароль вводится и **подтверждается дважды**; экспорт блокируется при несовпадении.
- Неверный пароль и повреждение дают **один** безопасный код (без oracle).
- Пароль нигде не сохраняется/не логируется/не уходит принтеру; потерянный пароль невосстановим.

Запрещено: пустой пароль как ключ, постоянный пароль приложения, общий секрет в EXE, авто-ключ
рядом с копией, DPAPI как единственный способ (копия переносится на другой компьютер), выдавать
незашифрованный payload за защищённый, XOR/ZIP-password/Fernet/самописная крипто.

## Импорт (v1 и v2)

Режим определяется по **безопасному header**, а не по расширению или наличию текста в payload:

- **v1** → всегда запрашивает пароль (`requires_password=true`).
- **v2 `none`** → пароль не показывается и не требуется.
- **v2 `password_aes256gcm`** → запрашивает пароль.

На первом шаге читается ТОЛЬКО header (`inspect`). Контейнер из будущей версии
(`container_format_version` > поддерживаемой) и неизвестный `protection_mode` → безопасный отказ
**без частичного применения**. Восстановление остаётся атомарным (план → подтверждение → apply
с журналом отката → verify), только для system-admin и локально (loopback); при активной печати
запрещено; rate-limit на попытки расшифровки применяется только к password-режиму.
