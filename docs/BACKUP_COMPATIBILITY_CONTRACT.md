# Контракт совместимости резервных копий — НЕИЗМЕНЯЕМЫЕ ПРАВИЛА

**Введён в Alpha 2.827. Обязателен к соблюдению во всех будущих версиях.**

Резервная копия конфигурации — это обещание пользователю: *копию, снятую сегодня, приложение
восстановит и через годы, и после смены мажорной версии.* Ферма в продакшене — цена нарушения
контракта — потерянные пользовательские настройки и доступы к принтерам. Ниже — правила, которые
защищают это обещание. Они сильнее удобства кода.

Спецификация первого формата: [BACKUP_FORMAT_V1.md](BACKUP_FORMAT_V1.md).

## Правило 1. Опубликованный формат неизменен

Как только версия формата (`container_format_version`, `payload_schema_version`, схема секции или
адаптера) выпущена, смысл её байтов **заморожен навсегда**. Нельзя переопределять поля, менять
единицы, переиспользовать имена под новый смысл или ужесточать разбор старой версии.

## Правило 2. Изменения — только повышением версии + миграцией

Несовместимая структура → **увеличить** соответствующую версию и **ДОБАВИТЬ** миграцию
`vN → vN+1` в `app/config_backup/migrations/`. Версии секций/адаптеров растут независимо и
**никогда** не равны `APP_VERSION`.

## Правило 3. Миграции append-only, чистые, детерминированные

- Миграции только **дописываются**: `v1→v2`, `v2→v3`, … Опубликованную миграцию **нельзя**
  переписывать или удалять **никогда**.
- Миграция — чистая функция `dict → dict`: без времени, сети, случайности, БД и `server.py`.
- Новые поля получают значения по умолчанию; смысл старых полей не меняется.
- Так копия v1 приводится к текущей схеме цепочкой `v1→…→current` **без участия старого кода**.
- Пропуск миграции в цепочке → явная ошибка `migration_missing`, а не тихая порча.

## Правило 4. Замороженные фикстуры неприкосновенны

`tools/fixtures/config_backup/vN/` содержит эталонные копии, снятые один раз. Их SHA-256
зафиксирован. **Никогда не менять и не перегенерировать опубликованную фикстуру.** Для каждой
выпущенной версии формата фикстура обязана существовать вечно, а
`test_config_backup_compatibility_forever.py` — вечно её восстанавливать. Красный тест
совместимости чинят **добавлением миграции в КОД**, а не правкой фикстуры.

При выпуске новой версии формата: добавить НОВУЮ фикстуру в новой папке `vN+1/`, сохранив все
предыдущие.

## Правило 5. Каждая постоянная настройка — в реестре

Любая новая постоянная пользовательская настройка ядра регистрируется в
`app/config_backup/settings_registry.py` с классификацией (portable / machine_bound /
operational / secret_derived и поведение восстановления). Иначе
`test_config_backup_contract.py` краснеет: копия молча теряла бы настройку.

## Правило 6. Безопасность важнее удобства

- **Credentials никогда не хранятся в открытом виде.** Секреты (токены/checkcode/API-ключи
  принтеров) — только внутри AES-256-GCM.
- **Пароль копии** никогда не сохраняется, не логируется и не отправляется в запросы к принтерам.
- **Потерянный пароль восстановить невозможно** — UI обязан честно предупреждать.
- **Без oracle:** неверный пароль и повреждение неотличимы (единый код).
- **Новые деструктивные/сетевые функции импортируются как OFF** (например,
  `printer_files_delete_enabled`).
- Данные из копии — **данные, не команды**: никогда не исполняются; строгий разбор контейнера.
- Экспорт/восстановление — только system-admin и только локально; restore запрещён при активной
  печати; применяется атомарно с журналом отката.

## Правило 7. Криптоконтракт только на проверенных примитивах

scrypt + AES-256-GCM из библиотеки `cryptography`. Никакого самописного шифра, XOR, Fernet,
ZIP-пароля или «только HMAC». Если в будущей среде AES-GCM нельзя безопасно встроить — резервное
копирование **останавливается** (никаких «копий» открытым текстом).

## Правило 8. Версии контейнера v1 и v2 постоянны (Alpha 2.828)

- **container v1 (payload.enc, всегда зашифрован) НЕ изменяется** — ни байт формата, имён записей,
  крипто, KDF-параметров, структуры header, семантики payload, reader v1, frozen fixture v1, её
  SHA-256, тестовой passphrase, опубликованных миграций и смысла v1-документа. **v1 читается навсегда.**
- **container v2 (payload.bin) добавлен как новый основной контейнер.** После выпуска Alpha 2.828 он
  тоже **заморожен**: reader v2 остаётся навсегда, спецификация — [BACKUP_FORMAT_V2.md](BACKUP_FORMAT_V2.md).
- **Оба ридера (v1 и v2) постоянны.** Для каждой выпущенной версии контейнера обязан существовать
  reader; удаление любого ридера краснит тест совместимости.
- **Несовместимое изменение — только НОВОЙ версией контейнера** (v3 …), не правкой v1/v2.
- **Режим `none` (без пароля) содержит чувствительные данные подключения** — это осознанный контракт;
  UI обязан честно предупреждать, а importer — заново валидировать (SHA/CRC защищают лишь от
  случайного повреждения, не от подмены).
- **Никакой тихой конвертации** между защищённым и незащищённым режимами: режим выбирает пользователь.
- **Исторические фикстуры всех версий не меняются никогда** и **авто-перечисляются** тестом
  совместимости (папки `vN/` подхватываются сами; изменение файла/хэша краснит тест).

## Правило 9. Данные модулей и неизменность проектов/задач (Alpha 2.829)

- **Payload schema v2** добавила секцию `module_data` (настройки + пользовательские данные
  модулей). Контейнеры v1/v2 при этом НЕ изменены; версия payload живёт в манифесте и
  мигрируется append-only цепочкой.
- **Старые копии без module_data** (payload v1, 2.827–2.828) мигрируются с секцией
  **ОТСУТСТВУЕТ (None)** — данные модулей на цели НЕ очищаются и НЕ заменяются пустым;
  семантика «replace with empty» запрещена навсегда.
- **Каждый persistent-модуль обязан иметь постоянный версионированный provider**
  ([MODULE_BACKUP_CONTRACT.md](MODULE_BACKUP_CONTRACT.md)); молчаливый пропуск модуля запрещён —
  полный export без provider блокируется с именем модуля.
- **Схемы module-backup постоянны**, миграции модулей append-only, module-фикстуры неизменяемы.
- **Проекты/задачи/файлы проектов/managed-хранилище/история печати** в копию не входят и
  restore их не меняет: fingerprint до/после, расхождение → полный откат.
- **Multi-store restore — одна операция**: pre-image каждого хранилища, порядок core→модули,
  откат в обратном порядке всех хранилищ, verify каждого отката.
- **Физический архив DATA_DIR не является пользовательской резервной копией** (обходит
  миграции, несёт machine-bound пути/runtime; допустим только как внутренний rollback pre-image).

## Проверки, стоящие на страже контракта

| тест | что гарантирует |
|------|-----------------|
| `test_config_backup_contract.py` | крипто (round-trip, no-oracle, no-leak, KDF-границы), строгий контейнер, полнота реестра, типы/исключения сериализатора |
| `test_config_backup_v1.py` | замороженные константы формата v1, валидатор (отказ будущим версиям, дубликатам), append-only миграции |
| `test_config_backup_v2.py` | v1-регрессия, структура v2, passwordless + protected режимы, импорт по header, UI-надписи, restart, sentinel |
| `test_config_backup_restore_atomicity.py` | план только читает; apply атомарен; сбой → полный откат; журнал complete после успеха; recovery на старте |
| `test_config_backup_compatibility_forever.py` | АВТО-перечисление v1 и v2: каждая замороженная фикстура восстанавливается всегда (SHA-256 + сквозной restore) |
| `test_config_backup_mutation_proof.py` / `_v2_mutation_proof.py` | порча любого инварианта краснит тест (тесты не вакуумны) |
