# Основа платных модулей FM: подписанные пакеты и лицензии

Состояние на 26.09.2026 (Alpha 3.0). Для разработчиков модулей и сопровождающих ядра.
Пользовательская сторона — [docs/user/licenses.md](../user/licenses.md).

## 1. Что это и чего это не даёт

Ядро FM бесплатное и открытое (MPL 2.0). Модули бывают бесплатные, платные и с бесплатной и
платной частью. Основа нужна, чтобы:

- ставить официальный пакет модуля только целым и неизменённым — проверка подписи и каждого
  файла **до** запуска кода модуля;
- продавать модуль «навсегда + период обновлений»: купленные выпуски работают бессрочно, новые —
  пока идёт оплаченный период;
- работать **полностью без интернета** после получения файла лицензии: ни регистрации, ни
  периодических проверок на сервере поставщика.

Чего это **не даёт** и не обещает:

- Ядро открытое. Его можно пересобрать и убрать любую проверку. Поэтому платный компонент
  проверяет лицензию **сам**, внутри своей платной операции, и ответу ядра не верит (раздел 7).
- Офлайн-программу нельзя сделать невзламываемой: платный компонент тоже можно исследовать и
  изменить. Цель — защита от простого копирования, подделки лицензий и обхода обычного
  интерфейса, а не абсолютная защита.
- Модуль работает внутри процесса ядра. Подпись подтверждает происхождение и целостность
  пакета; это не песочница — проверенный код может всё, что может ядро.
- Модуль, целиком написанный на JavaScript для браузера, защищён слабее: его код лежит у
  пользователя в браузере. Ценную логику держите на стороне сервера модуля.
- Файлы `web/` модуля браузер получает открытым текстом — их может прочитать каждый, кому
  доступен интерфейс программы. Ключей, платной логики и прочего ценного в `web/` не кладут.

### Лицензия SDK — MPL-2.0 (16.10.2026, R-149)

`app/licensing/fm_license_sdk.py` и `app/licensing/fm_paid_guard.py` — под Mozilla Public License 2.0,
как всё ядро; второй лицензии у них нет. В начале каждого файла стоит тот же заголовок
(`SPDX-License-Identifier: MPL-2.0`, правообладатель, ссылка на текст MPL), который выгрузка
открытой копии (`tools/public_export.py`) ставит остальным файлам; он в первых 600 байтах, поэтому
выгрузка второй не добавит. MPL — лицензия на уровне файла: платный модуль кладёт в свой пакет
копию этих файлов **без изменений** (`tools/module_package.py --embed-sdk` копирует байты), а
остальной код модуля может быть под любой лицензией — это «более крупное произведение» по
разделу 3.3 MPL. Изменённую копию SDK распространять можно только вместе с её исходным кодом.
Собственные платные модули поставщика это не ограничивает: права на SDK у него же. Проверка —
`tools/test_licensing_foundation.py` (V0c: заголовок на месте, копия в пакете совпадает байт в байт).

## 2. Кто за что отвечает

| Кто | Что делает |
|---|---|
| Ядро FM (открытое) | Проверяет пакет при установке и перед каждым запуском, хранит файлы лицензий как есть, показывает статусы, штатно закрывает платные маршруты (402), не заменяет рабочую версию неоплаченной |
| Платный компонент | Сам проверяет подпись лицензии своими вшитыми ключами, право на функцию, редакцию и **свой** выпуск, привязку — перед каждой платной операцией |
| Поставщик | Держит закрытые ключи (отдельно от проекта), выпускает лицензии и подписанные пакеты утилитами `tools/fm_license_tool.py` и `tools/module_package.py` |

## 3. Подписанный документ

Лицензия и паспорт пакета — одинаковые по устройству документы JSON:

```json
{"format": "fm-license | fm-package", "v": 1,
 "payload": { ...подписываемые поля... },
 "sig": {"alg": "Ed25519", "key_id": "<id доверенного ключа>", "value": "<base64url подписи>"}}
```

- Подпись Ed25519 (RFC 8032) над байтами
  `b"FM-SIGNED-V1\n" + format + b"\n" + canonical(payload)`. Разные форматы — разные области
  подписи: подпись паспорта нельзя выдать за подпись лицензии.
- `canonical` — JSON с ключами по порядку, без пробелов, UTF-8; дробные числа запрещены.
- `payload.key_id` обязан совпадать с `sig.key_id`. Открытый ключ из самого документа **никогда**
  не принимается: ключи берутся только из доверенного набора.
- Ключи лицензий и ключи пакетов — разные (`purpose`: `license` / `package`).
- Любое лишнее или недостающее поле, незнакомое значение, неверная дата — отказ. Отсутствие даты
  не означает «бессрочно».

Проверка — `app/licensing/fm_license_sdk.py`. Файл самодостаточен (стандартная библиотека +
`cryptography`), без импортов FM и без сети: платный компонент кладёт его **копию** в свой пакет.

## 4. Лицензия (`fm-license`)

| Поле | Обязательно | Смысл |
|---|---|---|
| `schema_version` | да | `1` |
| `product_id` | да | `3diwell-fm` |
| `license_id` | да | уникальный номер, имя файла `<license_id>.fmlic` |
| `customer_ref` | нет | внутренний номер покупателя, до 128 знаков, без лишних личных данных |
| `grants` | да | `[{module_id, edition, features}]`; `features: ["*"]` — все функции редакции |
| `use_type` | да | `perpetual` (бессрочно) или `term` (на срок) |
| `use_valid_from`, `use_valid_until` | только для `term` | срок использования; у бессрочной их быть не может |
| `updates_before` | да | исключающая верхняя граница даты выпуска доступных обновлений, UTC |
| `release_scope` | нет | `{"max_major": N}` — не выше основной версии N |
| `channel` | нет | `stable` (по умолчанию) или `beta` |
| `installation_binding` | нет | `{"install_id": "..."}` — лицензия только для этой установки |
| `issued_at`, `key_id` | да | дата выдачи и ключ поставщика |

Даты — строго `ГГГГ-ММ-ДДTчч:мм:ссZ`.

### Право на выпуск

Выпуск доступен, если

```text
release.released_at < license.updates_before
```

и совпадают модуль, редакция, канал, ограничение версии, привязка, а у срочной лицензии идёт срок
использования. Сравниваются **две подписанные даты**, а не часы компьютера: бессрочная лицензия
от часов не зависит вовсе. Пример: обновления до `2027-10-01` — выпуск от 20.09.2027 работает
всегда, в том числе при повторной установке в 2028 году; выпуск от 10.10.2027 требует продления.
Продление — новый файл лицензии с новой границей; прежние остаются и продолжают действовать.

Выпуск передаётся в проверку **обязательно** (`evaluate(..., release=...)`); без него — отказ
`release_required`. Коммерческий компонент передаёт выпуск, вшитый в свой код, а не файл с диска.

Коды отказа: `no_grant`, `edition_not_granted`, `feature_not_granted`, `use_not_started`,
`use_expired`, `time_required`, `binding_mismatch`, `channel_not_granted`, `release_scope`,
`update_not_covered`, `release_required`, а при разборе — `malformed`, `wrong_format`,
`unknown_key`, `bad_signature`, `wrong_product`, `unknown_field`, `missing_field`, `bad_value`.

## 5. Пакет модуля (`fm-package.json`)

Паспорт лежит в корне папки модуля. Поля: `schema_version`, `product_id`, `module_id`, `edition`,
`version`, `channel`, `released_at`, `core_contract`, `licensing: {model, paid_features}`
(`model`: `free` | `paid` | `freemium`), `entry: {backend, web}`, `files: {путь: sha256}`, `key_id`.
Правка `paid`/`edition`/файла обычным редактором ломает подпись.

Платный пакет несёт копии `fm_license_sdk.py` и `fm_paid_guard.py` под MPL-2.0 — неизменёнными, со
своим заголовком лицензии (раздел 1, «Лицензия SDK»).

### Политика пакетов в ядре

| Пакет | Установка | Запуск |
|---|---|---|
| Без паспорта (старые, сторонние, разработческие модули — все модули 3.0) | как раньше | как раньше; платных функций нет |
| Подписан доверенным ключом, файлы совпадают | ставится | код исполняется из проверенных байтов |
| Подпись не сходится, файл изменён, дописан или пропал | **не ставится**, рабочая версия цела | **не запускается**, состояние `integrity_failed`, данные модуля целы |
| Подписан неизвестным ключом (например, тестовым в собранной программе) | не ставится | не запускается, `package_untrusted` |

Установка распаковывает архив в отдельную папку (`DATA_DIR/modules_staging`), проверяет там и
только потом заменяет рабочую версию; прежняя сохраняется в `DATA_DIR/modules_previous/<id>`
(переустановка того же выпуска её не затирает). Кратковременную блокировку файлов Windows
замена переживает повтором; если замена всё же оборвалась, журнал `modules_staging/<id>.swap.json`
возвращает прежнюю версию на место при следующем запуске программы.
Архив с именами, которые Windows сливает в один файл (`backend.py` и `BACKEND.PY`, `backend.py.`),
или с зарезервированными именами (`CON`, `NUL`…) не ставится.

**Неоплаченное обновление не заменяет рабочую версию**: если прежний выпуск платного модуля покрыт
лицензией, а новый — нет (`update_not_covered`), установка отказывает, прежняя версия работает.

**Кэш Python.** Подложенный `.pyc` в `__pycache__` Python исполнил бы вместо проверенного
исходника. Для подписанного пакета ядро: убирает `__pycache__` перед запуском, грузит
`backend.py` и соседние файлы из проверенных байтов (сверка хеша при каждом чтении), не читает и не
пишет байт-код, отказывает в импорте файла, которого нет в паспорте. Отдельный `.pyc` вне
`__pycache__` — лишний файл, пакет не проходит проверку. Ресурсы `web/` подписанного пакета
отдаются, только если совпадают с паспортом.

## 6. Интерфейс ядра для модулей

`register(core)` получает объект `ModuleCore`. Для лицензирования (новых HTTP-маршрутов модулю не
нужно):

| Метод | Что даёт |
|---|---|
| `core.license_documents()` | байты всех файлов лицензий ровно в том виде, как их выдал поставщик |
| `core.license_revision()` | число, которое меняется при добавлении, удалении или замене лицензии |
| `core.install_id()` | номер этой установки (для лицензий с привязкой) |
| `core.package_document()` | байты проверенного ядром паспорта или `None` у пакета без подписи |
| `core.import_module_file(rel, name)` | загрузить соседний `.py`; у подписанного пакета — только из паспорта и из проверенных байтов |
| `core.add_paid_route(path, handler, feature, methods, policy_id)` | маршрут платной функции: без лицензии ядро отвечает 402 и обработчик не вызывает |
| `core.license_verdicts()` | (11.10.2026) байты подписанных ответов службы лицензий — платный компонент проверяет их сам |
| `core.license_machine()` | (11.10.2026) номер этого компьютера (64 hex), тот, что уходит в отметке |
| `core.license_status()`, `core.feature_allowed(feature)` | **взгляд ядра** — для подсказок и планирования, не для защиты |

HTTP для окна настроек (только администратор): `GET /api/licenses` (лицензии, номер установки,
запрос активации, статусы платных модулей), `POST /api/licenses/import` (файл `.fmlic`),
`DELETE /api/licenses/{license_id}`. В `GET /api/modules` у каждого модуля поле `licensing`.

## 7. Контракт независимой проверки в платном компоненте

Перед каждой платной операцией (маршрут, фоновая задача, отчёт) компонент:

1. Берёт **свою** копию SDK и **свои** вшитые данные: `fm_license_sdk.py` и `fm_embedded.py`
   (`EMBEDDED_RELEASE` — модуль, редакция, версия, канал, дата выпуска; `TRUSTED_KEYS` — открытые
   ключи поставщика). Оба файла кладёт в пакет упаковщик и покрывает подписью.
2. Проверяет паспорт своего пакета (`core.package_document()`) своим ключом пакетов и
   совпадение с `EMBEDDED_RELEASE` (`embedded_release_matches`); сверяет файлы своей папки
   (`verify_installed_package`).
3. Проверяет каждую лицензию (`core.license_documents()`) своим ключом лицензий.
4. Решает `best_decision(..., feature=..., edition=..., release=EMBEDDED_RELEASE,
   install_id=core.install_id(), now=...)`. Нет права — отказ; ядру не верит.

Пример — [examples/modules/demo_paid/backend.py](../../examples/modules/demo_paid/backend.py).

**Готовая самопроверка (11.10.2026)** — `app/licensing/fm_paid_guard.py`. Упаковщик с `--embed-sdk`
кладёт её копию в пакет рядом с SDK; `fm_embedded.py` теперь несёт и модель (`EMBEDDED_LICENSING`).
Модуль в `register()`:

```python
g = core.import_module_file("fm_paid_guard.py", "fm_<id>_paid_guard")   # нет файла — модуль бесплатный
_paid = g.load(core, "fm_<id>")                                        # None, если модель free
if _paid is not None:
    core.add_route = _paid.route_adder(core.add_route)   # модель paid: изменяющие маршруты — за границей, GET открыт
# модель freemium: route_adder ничего не оборачивает — платные маршруты модуль оборачивает сам: _paid.wrap(handler, feature)
```

`PaidGuard.check()` проверяет паспорт, свои файлы, лицензии и ответы службы для этого компьютера
(`core.license_verdicts`, `core.license_machine`) и кэширует решение на 10 секунд (сверку файлов — на 5
минут; неудачная — перепроверяется через 10 секунд). Без права изменяющий маршрут отвечает 402 с `checked_by: "module"`, просмотр работает; в печатных
хуках платная часть пропускается (`not _paid.check()[0]`). Так подключены «Складской учёт» 1.7.39 и
«Расчёт заказа» 0.2.3; у обычных сборок этих модулей (без вшитых файлов — все выпуски до сих пор) самопроверки
нет, они бесплатные.
Проверка `tools/test_licensing_foundation.py` (раздел 7) подменяет ядро «лицензия есть» и
убеждается, что компонент всё равно отказывает без настоящего документа, с подделанным
документом, с чужим паспортом выпуска и с дописанным файлом.

Правила для платного компонента:

- Соседние файлы подписанного модуля грузите через `core.import_module_file(...)` или обычным
  `import` (папка модуля в `sys.path`), а не `importlib.util.spec_from_file_location`: только
  так файл берётся из проверенных байтов. Двоичные расширения (`.pyd`) сверяются перед загрузкой,
  но читаются с диска ещё раз — это предел.
- Отказ лицензии **не останавливает печать**: в печатных хуках (`pre_print_check`,
  `after_dispatch`) платная часть просто не выполняется, печать идёт как без модуля.
- Отказ лицензии **не удаляет и не прячет данные**: пользователь может выгрузить свои данные
  обычными правами.
- Длительная операция, начатая при действующей лицензии, завершается штатно.
- У модуля с пользовательскими данными должен быть провайдер резервной копии
  (`app/config_backup/module_providers.py`), иначе полная копия настроек откажет.

## 8. Ключи

- В программе — только **открытые** ключи: `app/licensing/trust.py`, `PRODUCTION_KEYS`. Сейчас
  список **пуст**: ни одна платная лицензия и ни один «официальный» пакет рабочей программой не
  принимаются, пока поставщик не создаст ключи и не впишет их открытые части.
- Тестовые ключи принимаются только при запуске из исходников и только если переменная
  `FM_LICENSE_TEST_KEYS` указывает на файл с тестовыми открытыми ключами. Собранная программа
  тестовые ключи не принимает ни при каких настройках. Окно лицензий предупреждает, когда
  тестовые ключи включены.
- Закрытые ключи хранятся вне проекта, зашифрованы паролем, в двух копиях. Утилиты отказываются
  читать и писать закрытый ключ внутри папки проекта и не записывают туда лицензии покупателей;
  `.gitignore` не пускает в git `*.pem`, `*.key`, `*.fmlic`, `keys/`, `secrets/`.
- Смена ключа: новый ключ добавляется рядом со старым; прежние лицензии проверяются прежним
  ключом, пока его не уберут сознательно.

## 9. Утилиты поставщика

```bash
python tools/fm_license_tool.py keygen --purpose license --key-id vendor-lic-2026 --out D:\keys
python tools/fm_license_tool.py sign-license --key D:\keys\vendor-lic-2026.pem --key-id vendor-lic-2026 --spec spec.json --out D:\issued\L-0001.fmlic
python tools/module_package.py --module-dir modules\quality --out quality-0.2.3.zip
python tools/module_package.py --module-dir examples\modules\demo_paid --out demo_paid.zip --sign-key D:\keys\vendor-pkg.pem --key-id vendor-pkg-2026 --released-at 2026-09-26T00:00:00Z --licensing freemium --paid-feature pro_report --edition pro --embed-sdk --embed-trust D:\keys\trust-public.json
python tools/fm_license_tool.py verify --trusted D:\keys\trust-public.json D:\issued\L-0001.fmlic
```

Упаковщик одинаково исключает кэш, журналы, базы, резервные копии, лицензии и ключи и даёт
одинаковый архив из одинаковых исходников.

## 10. Офлайн-активация

1. В FM: *Настройки → Модули → Лицензии модулей → Сохранить запрос активации* — файл с номером
   установки, версией программы и модулями, без имён, адресов и данных фермы.
2. Файл переносится на компьютер с интернетом или передаётся поставщику любым способом.
3. Поставщик выпускает подписанную лицензию (с привязкой к `install_id`, если нужна).
4. Файл `.fmlic` переносится на компьютер фермы и добавляется: *Добавить лицензию из файла*.
5. Дальше интернет не нужен — ни при перезапуске программы, ни компьютера.

Полностью автономная установка не узнает о возврате платежа или отзыве до получения новых данных.
Привязка к установке сдерживает простое копирование лицензии, но не полное клонирование
компьютера или виртуальной машины вместе с папкой данных.

## 11. Как подключить следующий платный модуль

1. Решить модель: `paid` (всё платное) или `freemium` (перечислить платные функции).
2. Маршруты платных функций объявить `core.add_paid_route(...)`; записи прав — в
   `app/route_policy_registry.py` (иначе при включённой защите входом маршрут доступен только
   администратору).
3. Внутри каждой платной операции — проверка раздела 7 (готовый образец — `demo_paid`).
4. Провайдер резервной копии для данных модуля.
5. Собрать подписанный пакет упаковщиком с `--embed-sdk --embed-trust`, указать дату выпуска.
6. Выпустить лицензию с `updates_before`; проверить на изолированном сервере
   (`tools/test_licensing_process.py` — образец сценария).

## 14. Продажа «вариант 3»: ключ, отметка, ответ службы (10.10.2026)

Концепт — `docs/release_prep/PAID_MODULES_SALES_CONCEPT.md`, договорённость с сайтом —
`docs/release_prep/SITE_LICENSING_BRIEF.md` (сайт, оплату и кабинет делает второй разработчик).

- **Ключ текстом.** `FMK1.` + base64url(zlib(JSON документа `fm-license`)). Вставляется в окне
  *Настройки → Модули → Лицензии модулей*; подпись проверяется сразу, интернет не нужен. Файл
  `.fmlic` принимается как раньше. Продление — тот же `license_id` с более поздним `issued_at`;
  более старый документ более новый не затирает. SDK 1.3 (11.10.2026): повтор ключа JSON, NaN, подпись
  не в каноническом base64url, сжатие не zlib, данные после конца потока и распаковка сверх 64 КиБ —
  отказ; права в лицензии уникальны, `customer_ref` — только `[A-Za-z0-9][A-Za-z0-9_.-]`.
- **Согласие.** Лицензия (ключ или файл) принимается только с согласием на передачу номера
  лицензии и номера компьютера (`consent=1`, даётся один раз, `licenses/consent.json`).
- **Номер компьютера.** Три части: `MachineGuid` Windows, UUID платы из SMBIOS, серийный номер
  системного тома — каждая в виде солёной свёртки; номер — свёртка частей. Решает плата: тот же
  UUID платы — тот же компьютер (переустановка Windows и замена диска номер не меняют); плата не
  читается — тот же, только если совпали обе другие части (`licenses/machine.json`); копия диска со
  всей папкой данных на другой плате даёт новый номер. Людям показывается `XXXX-XXXX`.
- **Отметка.** `POST <адрес службы>` с телом `{schema_version, product_id, license_id, proof,
  machine, module_id, module_version, fm_version, nonce, via}`; `proof` = sha256 строки подписи
  документа лицензии; версии — по шаблону службы (`wire_version`, пусто — «0»). Одна отметка на
  лицензию (модули одной лицензии занимают одно место). Напрямую — фоновый поток ядра; через браузер —
  страница FM у администратора относит отметку службе (CORS) и возвращает её ответ в
  `/api/licenses/import`. **Расписание (11.10.2026, стенд 043).** Каждая отметка — с новым случайным
  числом и уходит один раз (`LicenseService.take_due`): после неё ни прямой канал, ни браузер её не
  повторят до срока. Сроки: ответ получен — 6 часов; новый ключ или продление — сразу; нет связи —
  15 минут (и напрямую, и через браузер: страница сообщает «нет связи» — `relay_status=network`; без её
  сообщения отданная браузеру отметка тоже ждёт 15 минут); отказ службы (4xx) или непринятый ответ —
  6 часов; 429/503 — пауза для ВСЕХ отметок обоих каналов по Retry-After, секундами или датой HTTP (RFC
  9110, 10.2.3; дата в прошлом — 30 секунд). **С 17.10.2026 (ответ службы 043)** пауза ровно такая, как
  попросила служба, в том числе дольше суток: раньше срока программа не обращается; без заголовка,
  «0» или мусор — 15 / 5 минут; не меньше 30 секунд; предел — год (защита от явной ошибки). Рядом с
  концом паузы хранится, когда её поставили и на сколько (`marks.json`: `backoff_set_at`, `backoff_s`):
  запись не сходится или её нет — срок дальше суток считается испорченным; часы отстали (запуск
  компьютера до сверки времени, сброс часов) — конец паузы не пересчитывается и не сокращается, и после
  поправки часов раньше срока службы программа не обращается. Повторный ввод ключа, «Удалить» и «Добавить», частые открытия
  окна лицензий и смена канала паузу не обходят. Браузер сообщает исход программе полями `relay_*` того
  же `/api/licenses/import`; Retry-After он видит, только если служба открыла заголовок
  (`Access-Control-Expose-Headers: Retry-After`), иначе — 15 / 5 минут. Не больше 10 отметок в минуту
  на оба канала вместе (стенд 043: 20 в минуту с одной сети). Поток смотрит раз в 15 минут, в сеть —
  только когда пора. Ни одна ошибка связи права не меняет. Адрес — `app/licensing/trust.py`,
  `LICENSE_SERVICE_URL` (только https на 3diwell.com и поддомены); **пока пусто — программа никуда
  не обращается**. Из исходников для проверок — переменная `FM_LICENSE_TEST_SERVICE`.
- **Ответ службы `fm-verdict`.** Подписан ключом лицензий, своя область подписи. Принимается
  только на последнюю отметку этого компьютера (то же `nonce`, тот же `machine`, известная
  лицензия, не старше сохранённого) и не позже суток после неё. «Остановить»/«аннулирована» для этого
  компьютера закрывает платные функции (код `license_stopped`/`license_revoked`) — и в ядре, и в самом
  модуле; ответа нет — лицензия работает. Последний принятый ответ хранится, в том числе после удаления
  лицензии. Вложенная лицензия (продление) проверяется своей подписью и номером ДО записи: не прошла —
  отклоняется весь ответ; более старая более новую не откатывает; запись атомарная.
- **Окно лицензий.** Ключ, согласие, номер компьютера, состояние по ответу службы (и «работает» с
  временем ответа), раздел «Что передаётся» — отметки в том виде, в каком они уходят; `proof` на экране
  показан только началом.
- **Пределы.** Знающий человек может закрыть программе доступ к сайту или удалить сохранённый
  ответ — копия ключа тогда не обнаружится (решение владельца: ферма без интернета работает).
  Защита обнаруживает копию ключа при связи; она не мешает ввести один ключ на нескольких
  компьютерах без интернета и не отзывает автономную копию мгновенно.
- **Проверка для разработки.** Из исходников: `FM_LICENSE_TEST_KEYS` (тестовые открытые ключи),
  `FM_LICENSE_TEST_SERVICE` (адрес тестовой службы — 127.0.0.1 или https на 3diwell.com),
  `FM_LICENSE_TEST_RELAY_ONLY=1` (без прямой отметки — только через браузер). Собранная программа их не
  читает.
