# «Запомнить это устройство»: договорённость FM и приложения Android

Версия договорённости: **1** (FM Alpha 3.0, 26.09.2026). Для разработчика приложения FM Client.

## Зачем

Владелец: один раз ввести логин и пароль на телефоне. Дальше телефон входит сам, пока
разрешение не отозвано: выходом на телефоне или кнопкой «Отозвать» в FM. Пароль на
телефоне не хранится.

## Что даёт FM (договорённость 1)

1. **Признак поддержки.** `GET /api/auth/status` возвращает `"remember_device": 1`.
   Прежние версии FM этого поля не отдают: с ними приложение ведёт себя как раньше
   (8 часов).
2. **Просьба запомнить устройство.** В тело входа добавляются поля:
   ```json
   {"username": "...", "password": "...", "remember_device": true, "device_name": "Pixel 7"}
   ```
   `device_name` необязателен. Без него FM возьмёт модель телефона из User-Agent
   (`… Android 14; SM-S918B Build/…`) и покажет её в списке устройств. Не длиннее 64 символов.
3. **Ответ при успехе:**
   ```json
   {"ok": true, "user": {"username": "...", "role": "..."},
    "device": {"id": "dev_…", "name": "Pixel 7", "persistent": true}}
   ```
   Cookie `fm_session` при этом — **токен устройства**: начинается с `fmd_`, алфавит
   `[A-Za-z0-9_-]`, длина 47. `Max-Age` = 315 360 000 (10 лет). Срок задаёт не часы, а отзыв.
   Остальные запросы приложения ходят с той же cookie, ничего в них не меняется.
4. **Если FM не смог записать разрешение** (сбой диска), он выдаёт обычную сессию на 8 часов
   и отвечает `"device": null, "remember_device_error": "store_failed"`. Приложению нужно
   сказать об этом пользователю («вход только до закрытия приложения»), а не считать
   устройство запомненным.
5. **Проверка при запуске:** `GET /api/auth/status` с токеном устройства возвращает
   `authenticated: true` и `"device": {"id", "name", "persistent": true}`.
   - Простой не ограничен.
   - Перезапуск FM разрешение не снимает.
   - Роль берётся текущая, из базы FM.
   - Временный сбой базы FM даёт **503** (`{"error": "temporarily_unavailable"}`, `Retry-After: 5`),
     а не `authenticated: false`. На 503 сохранённый вход стирать нельзя: нужно повторить позже.
6. **Когда разрешение снимается** (дальше любой запрос с этим токеном получает 401, а
   `status` — `authenticated: false`):
   - выход на телефоне: `POST /api/auth/logout` с этим токеном;
   - кнопка «Отозвать» в FM: Настройки → Система → Доступ и аудит → Пользователи → «Запомненные
     устройства» (раздел виден при любом режиме интерфейса);
   - в FM сменили пароль или роль пользователя, отключили или удалили его. Разрешение привязано
     к отпечатку пароля, которым выполнен вход: сменился пароль — оно не действует, даже если
     отзыв не успел записаться на диск;
   - в FM выключили защиту доступа («Доступ и аудит» → «Выключить режим») или включили её заново;
     пока защита выключена, токены устройств не принимаются, а новые не выдаются;
   - повторный вход с этого же телефона: прежнее разрешение заменяется новым.

   В FM хранится только SHA-256 токена. Копия базы FM войти не позволяет.

## Что ожидается от приложения

1. Перед входом прочитать `GET /api/auth/status`. Если `remember_device >= 1`, предложить
   «Запомнить это устройство» с пояснением: вход сохранится, пока пользователь не выйдет или
   доступ не отзовут в FM. Если поля нет — вести себя как с прежними версиями FM.
2. При включённой галочке слать во входе `remember_device: true` и `device_name`.
3. Вход с `device.persistent == true` хранить без срока по часам телефона и проверять ответом
   `GET /api/auth/status` при запуске.
4. Стирать сохранённый вход только при `authenticated: false`. На 503 и на ошибки сети — оставить
   и повторить проверку позже; на 401 от других запросов сначала спросить `status`.
   Так же — с живым соединением `/ws`: отказ при подключении (HTTP 401/403 вместо `101`) или
   закрытие с кодом 1008 FM отдаёт и при временном сбое своей базы, и при отзыве. Поэтому и здесь
   сначала `GET /api/auth/status`, а стирать вход — только при `authenticated: false`.
5. «Выйти» — `POST /api/auth/logout`: FM этим снимает разрешение насовсем.
6. Сохранённый вход шифровать ключом, доступным только на разблокированном телефоне
   (`setUnlockedDeviceRequired(true)` с API 28; StrongBox, если есть, иначе обычное хранилище
   ключей). Вход без срока на украденном телефоне иначе работает до отзыва в FM.
7. Ответ `402` с `reason: "license_required"` (платная сборка склада без действующей лицензии)
   — не отказ операции: неотправленную операцию склада не удалять, показать «только просмотр»
   и повторить позже. Иначе истёкшая лицензия молча стирала бы отсканированную катушку.

Разбор текущей сборки приложения и конкретные правки в его коде — во внутренних заметках
разработки FM (в открытый репозиторий не входят).

## Что проверено на стороне FM и что нет

- Проверено набором `tools/test_remembered_devices.py`: выдача, проверка, переживание
  «перезапуска» (хранилище читается заново), все пути отзыва, привязка к паролю, сбой записи на
  диск и её повтор в фоне, ответ 503 при сбое базы, выключение и включение защиты, список
  устройств в FM.
- **Не проверено:** настоящий телефон с новым приложением. Такой версии приложения ещё нет:
  и 0.13.0, и 0.15.15 (разбор 10.10.2026) по-прежнему ограничивают вход 8 часами сами и полей
  `remember_device`/`device_name` не шлют.
