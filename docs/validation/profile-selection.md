# Выбор профиля проверки по риску

Инструмент отвечает на один вопрос: **какого объёма проверки достаточно для этой правки.**
Он ничего не выполняет — только классифицирует изменения и печатает план.

```bash
python tools/validation/select_profile.py --working-tree
```

---

## 1. Что это и чего это не делает

| Делает | Не делает |
|---|---|
| Определяет риск R0–R4 и профиль | Не запускает ни одной проверки |
| Объясняет причину для каждого файла | Не пишет файлы, не трогает config и БД |
| Печатает план команд | Не собирает EXE, не поднимает браузер |
| Спрашивает Git список файлов (по явному флагу) | Не подключается к принтерам и к сети |

**Dry-run не является выполненной проверкой.** У каждого шага плана стоит `executes: false`.
Команды запускает человек. Исполнителя (executor) в системе пока нет — это отдельный этап.

## 2. Риск и профиль

| Риск | Что это | Минимальный профиль |
|---|---|---|
| **R0** | Документация, журналы, конфигурация ассистента | FAST |
| **R1** | Стили, ассеты, тестовая оснастка, служебные инструменты | TARGETED |
| **R2** | Фронтенд-логика и шаблон, маршруты и права, модули | SUBSYSTEM |
| **R3** | Серверный runtime, общий код, адаптеры принтеров, сборка | RELEASE |
| **R4** | Печать, очередь, резервное копирование, миграции данных | RELEASE |

| Профиль | Состав |
|---|---|
| **FAST** | Синтаксис изменённого файла; балансы для `web/app.css` и `web/index.html` |
| **TARGETED** | FAST + тесты, прямо связанные с изменённой областью |
| **SUBSYSTEM** | TARGETED + тесты всей затронутой подсистемы |
| **RELEASE** | `python tools/release_gate.py` целиком, **без ослаблений**; при затронутой сборке — EXE и packaged proof |
| **HARDWARE** | RELEASE + подтверждение на реальном принтере. **Автоматически не проходится** |

Признаки `ui_required` / `build_required` / `hardware_required` — не профиль, а дополнительные
обязательства: интерфейс проверяется глазами или на стенде, сборка требует EXE, железо —
владельца на ферме.

## 3. Главное правило: максимум, а не первое совпадение

Один файл может совпасть с несколькими правилами, и файлов в правке обычно несколько.
Совпадения **объединяются**:

- риск — **максимальный** из совпавших;
- профиль — **самый строгий** из совпавших и не слабее минимума для итогового риска;
- признаки `ui/build/hardware` — **логическое ИЛИ**.

Правка `web/app.css` (R1) вместе с `app/printer_job_lifecycle.py` (R4) даёт **R4 / RELEASE**
и при этом сохраняет `ui_required = true`. Принцип «первое совпадение победило» здесь
не действует и был бы дырой: он позволял бы спрятать критический файл за безобидным.

## 4. Что происходит с неизвестным файлом

Незнакомый путь **никогда не даёт зелёный быстрый профиль**.

| Ситуация | Результат |
|---|---|
| Путь не описан в карте | R3 / RELEASE + предупреждение «добавьте правило» |
| Путь не описан **и лежит в критической области** | `blocked = true`, код возврата 3 |
| Путь вне репозитория или с `..` | `blocked = true` |

Критическая область перечислена в `fallback.critical_area_globs`: запуск и файлы печати,
оркестратор, резервное копирование, миграции, klipper. Блокировка означает, что
автоматический выбор запрещён и решение принимает владелец.

Если в карте указан тест, которого нет на диске, он **исключается из плана**, выдаётся
предупреждение и профиль **повышается**. Названия тестов не выдумываются.

## 5. Режимы вызова

```bash
python tools/validation/select_profile.py --files web/app.css app/utils.py
python tools/validation/select_profile.py --files-from changed.txt
python tools/validation/select_profile.py --working-tree --json
python tools/validation/select_profile.py --staged
python tools/validation/select_profile.py --base 287b2ea
```

Режимы взаимоисключающие. `--working-tree`, `--staged` и `--base` — единственные случаи,
когда запускается подпроцесс, и только `git`. Обратный слэш эквивалентен прямому,
дубликаты схлопываются.

Коды возврата: **0** — план построен · **2** — ошибка ввода или карты · **3** — `blocked`.

## 6. Примеры

```
web/app.css                              -> R1 / TARGETED, ui=true
web/app.js                               -> R2 / SUBSYSTEM, ui=true
app/printer_job_lifecycle.py             -> R4 / RELEASE
app/project_orchestrator.py              -> R4 / HARDWARE, hw=true
3diwell-setup.iss                        -> R3 / RELEASE, build=true
app/some_unmapped_widget.py              -> R3 / RELEASE + предупреждение
app/print_supervisor_unmapped.py         -> blocked, rc=3
```

Поля JSON: `risk`, `profile`, `ui_required`, `build_required`, `hardware_required`,
`changed_files`, `matched_rules`, `unmatched_files`, `components`, `targeted_tests`,
`subsystem_tests`, `reasons`, `warnings`, `blocked`, `blocked_reason`, `plan`.

## 7. Как менять карту

Карта — `tools/validation/risk_map.json`, единственный источник правды.

- Риск **занижать нельзя** ради скорости; сомнение трактуется в сторону строгости.
- Тест, добавленный в правило, **должен существовать** — иначе покраснеет проверка 29.
- Правило с риском R3/R4 не может назначать профиль слабее RELEASE — проверка 30.
- `self_test: true` означает, что изменённый файл сам является тестом и попадает в план.
- После правки карты: `python tools/test_select_profile.py`.

## 8. Границы

Селектор — **советчик, а не власть**. Он не отменяет правил из
CLAUDE.md §3 и не ослабляет полный release gate. Профиль RELEASE
означает одну и ту же неизменяемую команду `python tools/release_gate.py`.

Выполнить безопасную часть выбранного профиля умеет исполнитель —
[profile-execution.md](profile-execution.md). RELEASE и HARDWARE он не запускает
никогда, а dry-run проверкой не считается. Для изменений интерфейса селектор
дополнительно сообщает покрытие по diff и статус квалификации UI-оснастки —
[ui-executor-integration.md](ui-executor-integration.md).
