# Критические области: печать, данные, резервное копирование

Читать **обязательно**, если задача касается запуска печати, очереди, восстановления,
базы данных, миграций, shared/core или серверного runtime.

**Для этих областей действует полный действующий цикл проверки без ослаблений** — точечных
проверок недостаточно. См. CLAUDE.md §3 и [release.md](release.md).

## 1. Зона повышенного риска: печать

`PrintStartDialog` / `printStart`, индикатор `sendJobs`, очередь поэтапного запуска
(`printQueue`), восстановление после перезапуска (recovery), `_send_file_to_printer` 🔒 —
менять **только по прямой задаче**, перечитав 🔒-маркеры. Попутные правки запрещены.

`_send_file_to_printer` — **единая** точка отправки файла на принтер. Обход этой точки
запрещён.

## 2. Данные

- SQLite-базы живут в защищённой `DATA_DIR` (вне папки программы): `farm_parts.db`,
  `farm_printers.db`, `farm_inventory.db`, `farm_quality.db`, `farm_cost.db`.
  Ежедневный авто-бэкап — в `DATA_DIR/backups`.
- Пути к БД получать **только** через `_resolve_db` / `core.resolve_db` (там миграция и защита).
- Новым модулям — своя БД; чужие таблицы не трогать.
- `DATA_DIR` руками не менять; изменение схемы БД — только с явным разрешением в тексте задачи
  (см. политику разрешений).

## 3. Предохранители

`DISPATCH_ENABLED`, `TRANSPORT_ENABLED` (`app/project_orchestrator.py`),
`PRINTER_FILE_DELETE_ENABLED_DEFAULT` (`app/printer_files/security.py`) — в исходнике `False`.

**Проверять по эффективному состоянию, а не по исходнику**: значения поднимаются настройками
владельца (`config.json`, таблица `app_settings`) на старте сервера. Доказательство «выключено»
делается исполнением функции решения против реального конфига, а не чтением константы.

Включать предохранители самостоятельно запрещено.

## 4. Контракт резервного копирования конфигурации

Формат `.3diwell-backup` — **постоянный публичный контракт**. Полные правила:
[BACKUP_COMPATIBILITY_CONTRACT.md](../BACKUP_COMPATIBILITY_CONTRACT.md); спецификации —
[BACKUP_FORMAT_V1.md](../BACKUP_FORMAT_V1.md), [BACKUP_FORMAT_V2.md](../BACKUP_FORMAT_V2.md),
[MODULE_BACKUP_CONTRACT.md](../MODULE_BACKUP_CONTRACT.md).
Чистое ядро — `app/config_backup/` (крипто, контейнеры и миграции **не** импортируют `server.py`).

- **container v1 и v2 постоянны.** v1 (payload.enc, всегда зашифрован) не меняется никогда;
  v2 (payload.bin, режимы none / password_aes256gcm) заморожен после выпуска. Для каждой версии
  контейнера обязан существовать reader. Несовместимость → **новая** версия (v3…), не правка
  v1/v2. Версия определяется по header, не по расширению.
- **Режим `none` содержит чувствительные данные подключения** — осознанный контракт: UI
  предупреждает, importer заново валидирует. Никакой тихой конвертации между защищённым и
  незащищённым режимами.
- **Исторические фикстуры всех версий не меняются никогда** и авто-перечисляются
  `test_config_backup_compatibility_forever.py`.
- **Само-проверка:** инвариант *export_success ⇒ same-version inspect/validate/plan_success* —
  экспорт делает полный обратный проход (`app/config_backup/self_check.py`) **до** выдачи файла;
  не прошло — файла нет, `audit=validation_failed`, никогда `result=ok`.
- Висячая **внутренняя** ссылка — не повреждение: запись сохраняется как есть, план даёт
  `dangling_internal_ref`. Фатальна только структурная порча. Наружу — только структурированный
  safe-ответ; `BackupError` никогда не unhandled 500.
- **Данные модулей:** модуль с пользовательскими данными обязан иметь постоянный
  версионированный backup-provider до выпуска; молчаливый пропуск модуля при экспорте запрещён
  (fail-closed с именем модуля). Схемы module-backup постоянны, миграции append-only.
  Старая копия без `module_data` **не очищает** данные модулей.
- Проекты, задачи, файлы и история печати в копию не входят; restore их не меняет
  (fingerprint-guard, расхождение → полный откат). Multi-store restore откатывается как одна
  операция. Физический архив `DATA_DIR` — **не** пользовательская копия.
- **Формат заморожен.** Несовместимость → повысить версию и **добавить** миграцию
  (append-only, чистую, детерминированную). Опубликованную миграцию не переписывать.
- **Замороженные фикстуры неприкосновенны** (`tools/fixtures/config_backup/vN/`, SHA-256
  фиксирован). Красный `test_config_backup_compatibility_forever.py` чинят миграцией **в коде**,
  не правкой фикстуры.
- **Каждая новая постоянная настройка ядра** регистрируется в
  `app/config_backup/settings_registry.py`, иначе `test_config_backup_contract.py` краснеет.
- **Безопасность:** credentials — только внутри AES-256-GCM; пароль копии не хранится, не
  логируется, принтеру не уходит; потерянный пароль невосстановим; неверный пароль и повреждение
  неотличимы (единый код); деструктивные и сетевые функции импортируются как OFF; данные копии —
  данные, не команды. Крипто — только scrypt + AES-GCM из `cryptography`.
- **Границы:** export / inspect / restore — только system-admin и локально (loopback); restore
  запрещён при активной печати, один за раз, атомарно с журналом отката.
- **Валидация:** пять тестов `test_config_backup_*` обязаны быть зелёными; при правке ядра —
  прогнать соответствующий mutation proof.

## 5. Klipper: повторная калибровка и покой

- Основание «операция управляется файлом» — **только видимая в файле команда**. Имя стартового
  макроса в шапке G-code доказательством не является (root cause Alpha 2.841).
- Недоказуемый стартовый макрос переводит калибровку на Farm Manager, а не отключает её.
- Покой перед стартом: `standby`, `complete`, `cancelled`. `printing`, `paused` и пустая строка
  покоем **не** считаются.
- Read-timeout после отправки запроса запуска = PENDING, а не отказ. **Автоматический повтор
  запрещён** — операция уходит в ожидание подтверждения.

Какой профиль нужен для конкретной правки — [profile-selection.md](profile-selection.md).
