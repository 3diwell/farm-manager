# Исполнение профиля проверки

Селектор отвечает на вопрос «что проверять». Исполнитель отвечает на второй вопрос:
**что из этого разрешено запустить без присмотра.**

```bash
python tools/validation/run_profile.py --working-tree
```

```bash
python tools/validation/run_profile.py --working-tree --execute
```

---

## 1. Selector и executor — разные вещи

| | [select_profile.py](../../tools/validation/select_profile.py) | [run_profile.py](../../tools/validation/run_profile.py) |
|---|---|---|
| Решает | какой профиль нужен | что из него можно выполнить |
| Запускает | ничего и никогда | FAST и доказанно безопасные тесты |
| Источник правды | `risk_map.json` | `test_catalog.json` + `command_registry.json` |

Исполнитель **не повторяет** логику риска: он вызывает селектор как модуль и работает с его
результатом. Изменение классификации делается в одном месте — в карте риска.

## 2. Статусы

| Статус | Что означает | Код |
|---|---|---|
| **PASS** | все обязательные проверки профиля реально выполнены и зелёные | 0 |
| **NO_CHANGES** | изменений нет, проверять нечего | 0 |
| **DRY_RUN** | план показан, **не выполнено ничего** | 0 |
| **FAIL** | выполненная обязательная проверка красная | 2 |
| **BLOCKED** | RELEASE, HARDWARE или неверная конфигурация — запуск не начинался | 3 · 5 |
| **PARTIAL** | безопасная часть выполнена, обязательные проверки остались | 4 |
| таймаут | шаг не уложился в бюджет; результат красный | 6 |

`3` — блокировка по профилю или риску. `5` — блокировка из-за конфигурации или ввода
(повреждённый реестр, устаревший каталог, путь вне репозитория). `6` — таймаут.

**PARTIAL — это не PASS.** **DRY_RUN — это не PASS.** BLOCKED не означает, что продукт
сломан, но задача при этом **не считается проверенной**.

## 3. Что выполняется, а что нет

| Профиль | Поведение |
|---|---|
| **FAST** | `py_compile` изменённых `.py`, `node --check` изменённых `.js/.mjs`, разбор изменённых `.json`, проверка ссылок изменённых `.md`. Всего проекта не запускает |
| **TARGETED** | FAST + связанные тесты, **только если каталог доказал их безопасность** |
| **SUBSYSTEM** | FAST + безопасные тесты подсистемы; небезопасные откладываются, итог PARTIAL |
| **RELEASE** | **ничего не выполняется**, BLOCKED, `release profile requires explicit future release executor` |
| **HARDWARE** | **ничего не выполняется**, BLOCKED, `manual hardware verification required` |
| `ui_required` | UI-тесты не запускаются никогда; итог не выше PARTIAL |

Отдельно от исполнителя существует изолированная проверка интерфейса —
[ui-verification.md](ui-verification.md). Она **не подключена** к `run_profile.py`:
признак `ui_required` по-прежнему даёт `PARTIAL`, а UI-сценарий запускается вручную.
Стабильность её сценариев подтверждена серией из десяти циклов
([ui-stability.md](ui-stability.md)). С этапа 3D UI-шаг можно выполнить флагом
`--with-ui`, но **только** когда квалификация действительна и каждый изменённый
участок интерфейса покрыт по diff — порядок в
[ui-executor-integration.md](ui-executor-integration.md). Без `--with-ui`, при
устаревшей квалификации и при неполном покрытии `ui_required` по-прежнему даёт
`PARTIAL`, а путь без diff покрытием не считается.

`web/app.css` и `web/index.html` откладываются: исполняемой команды для проверки балансов
в реестре нет, а выдумывать её нельзя.

## 4. Почему UI, RELEASE и HARDWARE закрыты

- **UI** требует браузера. Headless-Edge оставляет процессы при аварии, а убивать их по
  имени запрещено — это снесло бы браузер владельца. Автоматике здесь делать нечего.
- **RELEASE** — это час работы, 17 mutation proof и порча файлов репозитория по ходу.
  Запускать такое из фонового исполнителя нельзя: во время прогона `git status` показывает
  чужие мутации, и параллельная работа становится опасной.
- **HARDWARE** невозможно подтвердить программно: дефект 2.841 проявился только на живом
  K2 Plus. Результат подтверждает владелец на ферме.

Это границы этапа 2B, а не навсегда. Снимать их можно только отдельной задачей.

## 5. Как исполнитель защищён от произвольных команд

1. **Строка плана не исполняется.** Шаги строятся из структурных полей результата селектора
   (`changed_files`, `targeted_tests`, `subsystem_tests`), а не из текста `command`.
2. **Только реестр.** Выполнить можно лишь `command_id` из
   [command_registry.json](../../tools/validation/command_registry.json).
3. **argv-массив, не строка.** `shell=True` не используется нигде, поэтому пайпы, `&&`,
   `>` и подстановки оболочки невозможны в принципе.
4. **Алфавит литералов.** Аргумент реестра обязан состоять из `A-Za-z0-9._/-`. Пробел,
   кавычка и любой метасимвол отклоняются при загрузке реестра.
5. **Программу выбирает не пользователь.** `argv[0]` — всегда `sys.executable` или найденный
   `node`. Подставляемое значение может быть только параметром, никогда — программой.
6. **Путь проверяется.** Внутри репозитория, существует, нужное расширение; `..` и внешний
   абсолютный путь отклоняются.
7. **Тест — только из каталога.** Запустить можно лишь то, чья безопасность доказана.
8. **Минимальное окружение.** Дочерний процесс получает список разрешённых переменных;
   токены и ключи в него не попадают, а значит не попадают и в артефакты.
9. **Один процесс за раз.** Параллелизм на этом этапе всегда 1.
10. **Таймаут и завершение по PID.** Дерево процессов гасится через `taskkill /PID … /T /F`;
    завершение по имени процесса запрещено.

## 6. Каталог безопасности

[test_catalog.json](../../tools/validation/test_catalog.json) строится статически —
**ни один тест при этом не запускается**:

```bash
python tools/validation/build_test_catalog.py --check
```

```bash
python tools/validation/build_test_catalog.py --write
```

Классификация идёт по содержимому: для Python — по дереву кода, для `.mjs` — текстом.
Способность закрывает автозапуск, если тест поднимает браузер или сервер, ходит в сеть,
портит файлы, собирает EXE, трогает БД, запускает оболочку, вызывает неизвестную программу,
пишет через git или **импортирует `server.py`** — последнее особенно коварно: при
запущенной программе такой тест выходит с кодом 0 на именованном мьютексе до первой
проверки, то есть выглядит зелёным, ничего не проверив.

**Недоказанная безопасность — это не безопасность.** Всё, что разобрать не удалось,
получает `unknown capability`.

Каталог обязан быть актуальным: устаревший останавливает запуск с кодом 5. Ручные
исключения — [test_catalog_overrides.json](../../tools/validation/test_catalog_overrides.json);
исключение снимает **только перечисленные** способности и обязано иметь причину.

## 7. Артефакты

При `--execute` результат пишется в `logs/validation_runs/<run_id>/` (каталог игнорируется
Git): `summary.json`, `summary.txt`, `selector_result.json`, `execution_plan.json`,
`durations.json`, `environment.json`, а также `steps/NN_<id>.stdout.txt` и `.stderr.txt`.

В консоль выводится только сводка — полный вывод тестов лежит в файлах и не расходует
контекст. В `environment.json` попадает лишь список разрешённых имён переменных: значений
окружения владельца, DATA_DIR и данных принтеров там нет.

## 8. Примеры

```
docs/validation/*.md            -> R0 FAST      PASS      проверка ссылок, ~0.05 c
tools/validation/*.py + *.json  -> R1 TARGETED  PASS      4 шага, ~11 c
web/app.css                     -> R1 TARGETED  PARTIAL   UI проверяет человек
web/app.js                      -> R2 SUBSYSTEM PARTIAL   тесты поднимают браузер
app/project_orchestrator.py     -> R4 HARDWARE  BLOCKED   подтверждение на принтере
неизвестный app/*.py            -> R3 RELEASE   BLOCKED   полный gate запускает человек
пустой список                   -> NO_CHANGES
```

## 9. Ограничения этапа 2B

- Executor не запускает UI, RELEASE, HARDWARE, mutation proof, сборку и установщик.
- Безопасными признаны **30 тестов из 186**: остальные закрыты доказанными способностями.
  Это не оценка их качества — только пригодности к автозапуску без присмотра.
- `expected_max_seconds` — назначенный бюджет времени, а не измерение: тесты не запускались.
- Ни одного `.mjs` среди безопасных нет: JS разбирается текстом, а этого мало для
  доказательства.
- Параллелизма, очереди задач, worktrees и кэширования результатов нет и на этом этапе
  не предполагается.
