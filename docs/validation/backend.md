# Валидация бэкенда

Читать **только когда правишь** `server.py` или `app/**`.
Когда что запускать — CLAUDE.md §3.

## Обязательный минимум после правки

```bash
python -c "import py_compile; py_compile.compile('server.py', doraise=True)"
python -m py_compile app/*.py            # если менялись
```

Затем — существующие тесты, непосредственно связанные с изменённой функцией
(искать `grep -l "<имя_функции>" tools/test_*.py`).

## Ориентиры в `server.py`

выносить туда же.

## Ловушки, проверенные на практике

- **Ложно-зелёные offline-тесты.** Тест, импортирующий `server.py`, при живой программе делает
  `sys.exit(0)` на named mutex ДО проверок. `exit 0` ≠ PASS. Кодировка: `PYTHONIOENCODING=utf-8`,
  иначе cp1252 даст ложный `exit 1`.
- **Работающий процесс отстаёт от диска.** Правка `server.py` доезжает только после ручного
  перезапуска; сверять `/version` с `APP_VERSION`, прежде чем опираться на «релиз подтверждён».
- **Проверка «подстрока в исходнике» ловит свою же прозу** — докстроки и комментарии дают
  ложное совпадение. Считать вызовы или разбирать AST; обязателен мутационный прогон.
- **Окончания строк НЕ нормализуются и НЕ гарантированы.** `.gitattributes` хранит файлы
  побайтово (`* -text`), поэтому какие окончания попали в коммит — такие и лежат. Проверено
  22.08.2026: `server.py` был целиком CRLF, а с Alpha 2.863 лежит с LF (перевернулся при
  правке журнала «Что нового»). Измерено в тот же день: LF — всё, кроме двух файлов; CRLF
  остались у `app/project_orchestrator.py` и `web/app.css`.
  **Предполагать окончания запрещено — определять по самому файлу.** Многострочный якорь,
  записанный с `\n`, в CRLF-файле не находится НИКОГДА, и порча тихо превращается в «сбой
  оснастки»: так два набора теряли 3 порчи из 34 и 7 из 22, оставаясь красными и ничего
  не доказывая. Правильно — подогнать якорь под EOL конкретного файла (`_fit_eol`,
  подсчёт `\r\n` в исходнике или запасной вариант «не нашлось — попробовать CRLF»);
  за этим следит проверка D3 в `tools/test_mutation_proof_exit_contract.py`.
- **PowerShell-скрипты инсталлятора — только ASCII** (кириллица ломает PS 5.1).

## Протоколы принтеров (🔒, проверено на железе)

- **Bambu FTPS** — `storbinary` БЕЗ `conn.unwrap()` (Bambu не шлёт TLS close_notify);
  P1 путь `file:///mnt/sdcard/`; H2D/H2S/P2S — схема `ftp:///`.
- **FlashForge AD5M** — `POST /uploadGcode`, все метаданные в HTTP-заголовках, multipart
  с единственным полем `gcodeFile`, `Expect: 100-continue`.
- **Klipper/Moonraker** — загрузка и запуск одним POST; read-timeout после отправки означает
  PENDING, а не отказ; автоматический повтор запрещён.

Изменение любого из этих путей — критическая область,
см. [critical-runtime.md](critical-runtime.md).

Какой профиль нужен для конкретной правки — [profile-selection.md](profile-selection.md).
