# Модули-плагины: конструктор и политики

Читать **только когда работаешь с** `modules/**` или добавляешь крупную функцию.
Когда что запускать — CLAUDE.md §3.

## 1. Крупная функция → модуль-плагин (предпочтительный путь)

Встроенных модулей в программе **нет** (принципиальное решение владельца): любой модуль
ставится отдельно из `.zip` и так же удаляется. Единственный дом установленных модулей —
`DATA_DIR/modules/<id>/`. В репозитории `modules/<id>/` — это **исходники**, из них собирается
установочный `.zip`; в сборку `.exe` они не попадают.

```
modules/<id>/
  module.json      {"id","ru","en","version","icon","entry":"web/Panel.js",
                    "settings_entry":"web/Settings.js",               # необязателен
                    "launchers":[{"ru","en","icon","props":{...}}]}   # launchers необязательны
  backend.py       def register(core): ...
  web/Panel.js     окно модуля (Vue-компонент)
  web/Settings.js  ячейка настроек во вкладке «Настройки → Модули» (Vue-компонент)
```

**Окно и настройки — независимы (2.1002).** `entry` и `settings_entry` необязательны по
отдельности, но хотя бы одно должно быть, иначе модуль нечем показать:

| что объявлено | как выглядит для владельца |
|---|---|
| только `entry` | окно модуля; плитка в списке и (по выбору) кнопка на баре |
| `entry` + `settings_entry` | окно модуля плюс ячейка его настроек во вкладке «Модули» |
| только `settings_entry` | окна нет вовсе: модуль живёт одной ячейкой настроек, кнопки на баре не получает, в списке помечен «настройки ниже» (так сделан `messengers`) |

**API `core`:** `add_route(path, handler, methods)` → `/api/mod/<id>/<path>`;
`resolve_db(name)` — своя БД в защищённой папке; `new_id(prefix)`;
`printers()` и `printer_states()` — чтение фермы и AMS;
`add_hook(name, fn)` — подписка на хуки печати (все fail-open, ошибка хука не влияет на печать):
`'pre_print_check'` fn(printer_id, fdata, ams_slot, fname) → `None` = разрешить, dict со `status`
= блокирующий ответ; `'after_dispatch'` fn(printer_id, ams_map, fdata, fname) — после успешной
отправки, результат игнорируется.

**План подачи (16.09.2026).** `pre_print_check` дополнительно получает именованный `plan=` —
`{"slots": [слот по каждому филаменту], "external": bool, "source", "confidence"}`: из каких слотов
печать реально пойдёт (при запуске из очереди и пачкой `ams_slot` не задан вовсе). План уходит
**только** хукам, которые этот аргумент объявили; хук с четырьмя аргументами вызывается как прежде.
`slots: []` значит «подача не определена» — проверять нечего; `slots: None` — плана нет, ведите себя
как раньше; `confidence: "snapshot"` — план снят при постановке в очередь, к старту он мог устареть.

**Контракт окна:** default-export компонент, props `{ open, lang }`, событие `'close'`;
стили инлайном на CSS-переменных темы; иконки — глобальный `<svg-icon>`.

**Установка:** только «Настройки → Модули → Установить модуль (.zip)»; активация —
после перезапуска. Удаление — корзиной там же (файлы удаляются, БД модуля сохраняется).

## 2. Данные «модуль → ядро»: только провайдер/агрегатор

Ядро **не знает** про конкретные модули: из ядра **нельзя** делать fetch на `/api/mod/<id>/*`.
Модуль публикует данные через провайдер ModuleCore (`add_printer_badge_provider`,
`add_printer_filament_provider`), ядро опрашивает общий агрегатор (`/api/printer-badges`,
`/api/printer-filament`). Исключение провайдера логируется и глотается — ядро не падает;
модуль не установлен → пустой ответ → UI-блок скрыт. Регистрация провайдера — под
`hasattr(core, "...")`, чтобы модуль не падал на старом ядре.

Обратное направление: `core.get_printer_filament_snapshot(printer_id)` — read-only, fail-open,
отдаёт **глубокую копию** снимка привязанного филамента. Так модуль «Аналитика качества»
снимает материалы печати, не импортируя склад и не открывая его БД.

## 3. Деплой: репозиторий ≠ ферма

Рантайм грузит модули **только** из `DATA_DIR/modules/`. Правки `modules/<id>/*` доезжают до
фермы только через: `python tools/build_<id>_zip.py` → переустановка zip → перезапуск программы.

**После любой правки `modules/<id>/*`:** поднять `"version"` (patch) в `module.json`, вписать тот же
номер в `app/module_catalog.py`, пересобрать zip и **явно сказать владельцу переустановить модуль**.
Урок Alpha 2.704: провайдер «не работал», потому что на ферме стоял старый zip.

**Версия модуля больше не запрещает загрузку (26.09.2026).** Ставится и запускается любая версия,
старее или новее программы. Право маршрута берётся из карты прав по методу и адресу. Расхождение
номера с картой уходит в журнал заметкой. Маршрут, которого в карте нет, открыт только
администратору (`app/module_runtime_policy.py`). В «Настройки → Модули» под названием стоят
номер версии и пометки «есть новее» или «новее программы». Не загружается модуль только в трёх
случаях: без читаемого `module.json`, с негодным id или если его `backend.py` падает при запуске.
Проверки — `tools/test_module_version_tolerance.py` и `tools/test_module_core_contract.py`.

## 4. SVG-катушки склада

- Runtime-ассеты `modules/inventory/web/assets/spools/spool-{0,10,…,100}.svg` — **ровно 11**
  настоящих векторных SVG (никаких raster/base64/`<image>`).
- Пайплайн перекраски требует заливки филамента `#00A0E3`, без `url(#...)`-ссылок.
- `spool-states.generated.js` — аварийный codegen-артефакт: рантайм его **не импортирует**,
  в zip он **не входит**.
- Состав zip: `module.json`, `backend.py`, `web/InventoryPanel.js`, 11 SVG — без бэкапов,
  temp-файлов и папок «New folder».

## 5. UI-инварианты

- **Escape закрывает только верхний слой** (стек `escLayers` → цепочка в `onKeydown`, `app.js`).
  Новые окна обязаны встраиваться в стек; модалка recovery Escape игнорирует — не менять.
- **Разрушительные действия** (удаление принтера/проекта/файла/катушки, Stop печати) — только
  через confirm. Прятать в ПКМ можно, удалять функционал — нельзя.
- **ПКМ не ломает обычный клик**: `@contextmenu.prevent` на элементе, закрытие кликом мимо и
  Escape, у краёв экрана меню зажимается, на input/textarea остаётся нативное меню.
  Опасные пункты — `danger:true`.

## 6. Политика статистики качества (модуль `quality`)

- Отдельный устанавливаемый модуль; программа полноценно работает без него.
- **Ядро даёт только generic-события**: `app/print_run_events.py` (без SQL) формирует `run_id`
  и fail-open хуки `print_run_started` / `print_run_finished` (payload — копия; ошибка
  подписчика глотается). Ядро не знает про `/api/mod/quality/*`, fallback-эндпоинтов нет.
- Данные качества принадлежат модулю: `DATA_DIR\farm_quality.db`. Обновление/удаление кода
  модуля не удаляет БД.
- **Журнал иммутабелен**: строки только добавляются и один раз получают терминальный исход.
- **Материалы печати — только по фактическому назначению задания** (`material_assignments`
  события старта, сопоставленные с привязанной катушкой). Наличие катушки в AMS само по себе
  использованием **не является**; «все непустые слоты» не сохранять никогда. `confidence`:
  exact / probable / partial / unknown (при unknown не пишем). Общий вес не делить по слотам.
- Выводы требуют выборки и доверия; корреляция ≠ причина; «виноват» — только после
  подтверждения человеком. Не-качественные исходы исключаются из рейтингов, оставаясь
  в затратах. `schema_version` — в каждой строке; backfill маркируется `origin='backfill'`.

## 7. Расчёт заказа (модуль `cost`, с 3.0)

12.09.2026 владелец удалил «Себестоимость печати» и поставил на её место «Расчёт заказа»
(исходники владельца) под тем же id `cost`: модуль сохранил имена, пути, методы и права
маршрутов. Версия 0.2.0 — чтобы ядро не подняло старую «Себестоимость», если она осталась на
ферме: та покажется «требует обновления», и достаточно поставить новый zip.

- Своя БД `DATA_DIR\farm_cost.db`: `orders`, `order_files`, `order_config`, `order_model_rates`,
  `order_printer_rates`, `order_printer_models`, `order_sequence`. Таблицы прежней
  «Себестоимости» (`cost_*`) модуль не удаляет и не переделывает; перед первой загрузкой один раз
  копирует прежнюю базу в `farm_cost_before_order_module_<время>.db`.
- Копии файлов заказов — `DATA_DIR\cost_order_files\<заказ>\`. Удаление заказа убирает только эти
  копии; проекты программы, созданные по заказу, не трогаются.
- К печати не подключается (хуков нет): печать от модуля не зависит.
- Задачи и проекты берёт у САМОЙ программы HTTP-запросами на `127.0.0.1:<порт сервера>` с
  заголовками сеанса пользователя (Cookie, Authorization, X-CSRF-Token); проект создаёт штатным
  импортом `/api/projects/import` и загружает в него файлы заказа. Host из запроса не используется,
  во внешнюю сеть модуль не ходит. Цены материалов окно модуля берёт у склада.
- Путь файла ЗАДАЧИ ядро не хранит (`staging_files.src_path` пуст): модуль ищет файл по имени в
  `DATA_DIR\temp_files`, затем `DATA_DIR\slicer_uploads` — так же, как само ядро в `/api/staging`
  (правка при включении в выпуск 3.0; без неё список задач в модуле всегда был пуст).
- Эффекты маршрутов в карте прав: FILESYSTEM и NETWORK у расчёта, сохранения и `recalc`, кэш
  моделей принтеров (DATABASE, NETWORK) у списка принтеров и ставки принтера. Доказательство —
  `tools/test_cost_module.py`, раздел I; там же расчёт сверен с независимой арифметикой.
- **Резервная копия (R-125):** провайдер ядра `cost` — backup v2 по настоящей схеме модуля:
  заказы, ставки моделей и принтеров, модели принтеров, счётчик номеров и настройки
  (`order_config`). Файлы моделей к заказам (`order_files`, `cost_order_files\`) в копию **не
  входят** — это написано в окне копии; вложения — решение владельца (контейнер v3). Старые копии
  v1 («Себестоимость») читаются: их данные уходят в extensions и не применяются. Поменял таблицы
  модуля — поправь `CostBackupProvider` (`app/config_backup/module_providers.py`): состав
  сверяется с DDL модуля в `tools/test_cost_backup_provider.py`.
- Сборка: `python tools/build_cost_zip.py` → `modules/3diwell-module-order-calculation.zip`
  (бэкенд, `order_calculator.py`, `order_parser.py`, окно).

## 8. Оформление и темы (модуль `appearance`, с 3.0)

- Только интерфейс: `module.json` и ES-модули в `web/`. Бэкенда и маршрутов нет — в карте прав
  ядра модуля нет, версию ядро не сверяет.
- Точка входа `web/AppearancePanel.js` импортируется ядром при загрузке страницы, как у любого
  модуля с окном; её верхний уровень запускает `bootstrapThemeRuntime`. Тема применяется ко всей
  программе, только если модуль включён: состояние сверяется по `/api/modules` раз в 10 секунд и
  при возврате в окно; модуль отключён или ответ не пришёл — стиль темы убирается. Аварийный
  выход — адрес с `?appearance=off`.
- Темы хранятся в браузере (`localStorage`, ключи `fm_appearance_*`): на сервер и в резервную
  копию не попадают, на другом компьютере переносятся файлом темы. В резервной копии модуль
  классифицирован «пользовательских данных нет» (`AppearanceBackupProvider`); без этого его
  установка блокировала бы полный экспорт — fail-closed, `docs/MODULE_BACKUP_CONTRACT.md`.
- Документы автора (`README_RU.md`, `IPHONE_THEME_NOTES_RU.md`, `QA_*.json`) лежат рядом с
  исходниками, но в zip не входят.
- Сборка: `python tools/build_appearance_zip.py` → `modules/3diwell-module-appearance.zip`;
  сборщик проверяет, что каждый относительный импорт разрешается в файл архива. Проверки —
  `tools/test_appearance_module.py`.

Какой профиль нужен для конкретной правки — [profile-selection.md](profile-selection.md).
