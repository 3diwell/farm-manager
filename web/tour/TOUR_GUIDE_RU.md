# 3DIWELL Farm Manager — инструкция по правкам обучения интерфейсу

> **Сейчас обучение выключено** (решение владельца 12.09.2026): флаг `TOUR_ENABLED = false` в начале
> `web/app.js`. Окно выбора при запуске не открывается, кнопки в «Настройки → Общие» спрятаны,
> `startTour` и `resumeTour` ничего не делают. Код тура и сценарий не удалены — перед доработкой
> поставить `true`.
>
> **Решение 16.10.2026: этот тур не включать обратно.** Причины:
> 1. Шаги написаны для интерфейса 2.0 (демо-проводник, развёрнутая карточка принтера, демо-сцены),
>    а основной интерфейс с 2.982 — 3.0; 2.0 остался только запасным `/?ui=2`.
> 2. Песочница тура опасна на живой ферме: на время тура настоящие принтеры, детали и проекты
>    подменяются демо-данными (тревоги настоящих принтеров не видны), а `window.fetch` подменён так,
>    что любой не-GET запрос к `/api/` получает поддельный ответ 200 `{}` — действие «удаётся», не
>    дойдя до сервера, в том числе в окнах модулей.
>
> Обучение в 3.0 — **подсказки при наведении** (`web/composables/helpHints.js`, у каждого
> `data-help` в разметке есть текст RU и EN, проверяет `tools/test_help_hints_coverage.py`). При первом
> запуске в панели «Подсказки» один раз предлагается их включить (карточка «Включить подсказки» /
> «Не нужно», отметка `farm_help_offer_v1` в браузере). Если понадобится пошаговый тур — это новая
> задача: короткий тур 3.0 не больше 7 шагов, только по настоящим элементам, без демо-данных и без
> подмены `fetch`.

## Главное правило

Обучение интерфейсу должно правиться так, чтобы не затрагивать рабочую логику приложения: принтеры, проекты, API, серверные расчёты, базы данных и обработчики печати.

Если для нового шага обучения требуется не просто изменить текст или подсветку, а поменять поведение приложения, демо-сцены, серверный код или реальные действия с файлами/принтерами, такую правку нужно считать потенциально рискованной и согласовывать отдельно.

## Какие файлы теперь отвечают за обучение

| Файл | Назначение |
|---|---|
| `web/composables/tourSteps.js` | сценарий обучения: полный тур, короткий тур, порядок, тексты, селекторы, группы и названия разделов |
| `web/app.js` | логика показа тура, демо-данные, измерение подсветки, защита от POST-запросов во время тура |
| `web/index.html` | элементы интерфейса и `data-tour`-метки, которые подсвечивает обучение |
| `web/app.css` | внешний вид подсветки, карточек, анимаций и демо-сцен |

## Режимы обучения

Сейчас есть два режима:

| Режим | Запуск | Назначение |
|---|---|---|
| Короткое обучение | `startTour('quick')` | быстрое первое знакомство с интерфейсом, 13 шагов |
| Полное обучение | `startTour('full')` | подробный тур по интерфейсу, 35 шагов |

Короткий тур не содержит копий шагов. Он собирается из полного тура по списку `quickTourStepIds` в конце файла `web/composables/tourSteps.js`.

Внутри карточки обучения теперь показывается текущий раздел, например «Проекты и производство · 2 из 8». В нижней панели есть кнопка «Пропустить раздел».

Чтобы изменить короткий тур, достаточно изменить список `quickTourStepIds`:

```js
export const quickTourStepIds = [
    'welcome',
    'connection-sync',
    'projects-overview',
    'finish'
];
```

Важно: в `quickTourStepIds` нужно указывать только существующие `id` из полного списка `tourSteps`.


## Разделы обучения

Названия разделов находятся в начале `web/composables/tourSteps.js`:

```js
export const tourGroupLabels = {
    basics: 'Basics',
    settings: 'Settings',
    printers: 'Printers',
    projects: 'Projects and production',
    quick_tasks: 'Quick Tasks',
    alerts: 'Suggestions and alerts',
    finish: 'Finish'
};
```

Если добавляется новая группа, нужно:

1. добавить её в `tourGroupLabels`;
2. добавить её в `tourGroupOrder`;
3. добавить русский перевод названия группы в блок `Object.assign(RU, {...})` в `web/app.js`;
4. обновить список допустимых групп в `web/tour/validate-tour.mjs`, если группа действительно новая.

## Навигация внутри обучения

Во время обучения доступны:

- кнопка «Назад»;
- кнопка «Далее»;
- кнопка «Пропустить раздел»;
- клавиши `←` и `→` для перехода назад/вперёд;
- клавиша `Enter` для перехода вперёд;
- клавиша `Esc` для закрытия обучения.

Эти клавиши работают только когда открыт тур. Если фокус находится в поле ввода, клавиши не перехватываются.

## Что можно безопасно менять в `web/composables/tourSteps.js`

Можно менять:

- порядок шагов;
- `title` и `text`;
- `card` — положение карточки подсказки;
- `sel` — если элемент уже существует в `web/index.html`;
- `group` и `id`;
- добавлять новые шаги, если они используют существующие элементы интерфейса.

Нельзя без отдельной проверки менять:

- серверные API;
- реальные действия с принтерами;
- загрузку файлов;
- подсчёт деталей;
- сохранение проектов;
- логику завершения печати;
- защиту `_tourBlockFetch`, которая блокирует не-GET запросы во время обучения.

## Формат шага

```js
{
    id: 'projects-label-objects',
    group: 'projects',
    sel: '#tour-demo-projcell',
    card: 'below',
    title: 'Automatic part counting',
    text: 'Automatic counting depends on data saved inside the print file...'
}
```

### Поля

| Поле | Обязательное | Описание |
|---|---:|---|
| `id` | желательно | стабильное имя шага для будущих правок |
| `group` | желательно | логическая группа: `basics`, `settings`, `printers`, `projects`, `quick_tasks`, `alerts`, `finish` |
| `sel` | да | CSS-селектор элемента, который нужно подсветить |
| `title` | да | английский ключ заголовка |
| `text` | да | английский ключ текста |
| `card` | нет | положение карточки подсказки |
| `view` | нет | `grid` или `list`, временно переключает вид принтеров |
| `scene` | нет | запускает демо-сцену |
| `expand` | нет | раскрывает демо-карточку принтера |
| `marks` | нет | показывает цифровые бейджи на кнопках |

## Переводы

Тур пока использует общий словарь `RU` внутри `web/app.js`. Для новых текстов в этой версии добавлен отдельный блок:

```js
Object.assign(RU, {
    "English text": "Русский перевод"
});
```

Если добавляется новый шаг с новым `title` или `text`, нужно добавить русский перевод в этот блок. Иначе в русской версии приложения этот текст будет показан на английском.

## Допустимые демо-сцены

| `scene` | Назначение |
|---|---|
| `diag` | демонстрация диагностики |
| `print` | демонстрация выбора файла и AMS-слота |
| `load` | демонстрация загрузки файла в Quick Tasks |
| `project` | статичная демо-панель проекта и подсчёта деталей, без API и базы |
| `attach` | старая сцена привязки файла к детали, сейчас не используется |
| `slice` | старая сцена открытия модели в слайсере, сейчас не используется |
| `reveal` | старая сцена открытия расположения файла, сейчас не используется |

Новые демо-сцены требуют правки `web/app.js`. Это уже не просто текстовая правка, поэтому перед добавлением новой сцены нужно отдельно проверить риски.


## Автоматическая проверка обучения

Для безопасных правок добавлен отдельный файл:

```text
web/tour/validate-tour.mjs
```

Он ничего не меняет в приложении и только читает файлы обучения. Проверяются:

- уникальность `id` у всех шагов;
- что `quickTourStepIds` ссылается только на существующие шаги полного тура;
- что `quickTourSteps` действительно собирается в том же порядке;
- что `group`, `scene`, `card` и `view` входят в разрешённые значения;
- что `sel` можно найти в `web/index.html`;
- что для каждого `title` и `text` есть русский перевод в словаре `RU`;
- что у каждой группы есть название раздела и русский перевод.

### Как запустить проверку

Из корневой папки приложения:

```bash
node web/tour/validate-tour.mjs
```

Или в Windows можно открыть файл:

```text
web/tour/validate-tour.bat
```

Если всё хорошо, будет результат:

```text
Результат: OK. Обучение прошло автоматическую проверку.
```

Если есть ошибка, скрипт покажет конкретный шаг и причину: например отсутствующий перевод, дублирующийся `id` или селектор, которого нет в `index.html`.

## Адаптация обучения под маленькие экраны

Адаптация находится в `web/app.css` в блоке:

```text
Адаптация интерактивного обучения для небольших экранов
```

Этот блок меняет только внешний вид overlay-обучения: размеры карточки, перенос кнопок нижней панели, скрытие клавиатурной подсказки на мобильных и ограничение ширины всплывающих подсказок. Он не меняет сценарий обучения, демо-данные, серверные запросы, принтеры, проекты или подсчёт деталей.

Дополнительно в `web/app.js` позиционирование карточки учитывает компактный экран: на узких или низких экранах карточка размещается сверху или снизу по центру, чтобы не уезжать за пределы окна.

## Раскрываемый блок «Подробнее»

Начиная с версии `tour_update_06`, у шага обучения может быть необязательное поле:

```js
more: 'Detailed explanation text'
```

Правило использования:

1. В `text` лучше оставлять короткое объяснение, которое пользователь видит сразу.
2. В `more` переносить длинные пояснения, примеры и уточнения.
3. Если у шага есть `more`, в карточке обучения появится кнопка «Подробнее».
4. При переходе на следующий шаг раскрытый блок автоматически закрывается.
5. Для `more` обязательно нужен русский перевод в `web/app.js`, иначе валидатор покажет ошибку.

Это изменение касается только карточки обучения. Оно не меняет сервер, API, принтеры, проекты, базы, подсчёт деталей или запуск печати.

Пример безопасной правки:

```js
{
  id: 'projects-label-objects',
  group: 'projects',
  sel: '#tour-demo-projcell',
  title: 'Automatic part counting',
  text: 'Automatic counting works best when the print file contains object labels from the slicer.',
  more: 'For reliable recognition, enable Label Objects / gcode_label_objects before exporting g-code or 3MF.'
}
```

## Обновление 07 — сохранение прогресса обучения

Добавлено локальное сохранение прогресса обучения в браузере.

Что изменилось:

- если пользователь закрыл обучение через `×`, `Esc` или просто не дошёл до конца, приложение запоминает текущий режим и шаг;
- в настройках появляется кнопка `Продолжить обучение`;
- если пользователь нажал `Готово` на последнем шаге, прогресс очищается;
- кнопка `Сбросить прогресс обучения` очищает сохранённый прогресс вручную.

Технически прогресс хранится только в `localStorage` браузера:

```js
farm_tour_progress_v1
```

Это не отправляется на сервер, не меняет базы данных, не влияет на принтеры, проекты, Quick Tasks или подсчёт деталей.

При изменении списка шагов безопаснее опираться на `id` шага, а не на номер. Поэтому прогресс сохраняет и `stepId`, и `stepIndex`. Если порядок шагов изменится, приложение попробует восстановить место по `stepId`.

## Этап 8 — стартовое окно выбора обучения

Добавлено стартовое окно обучения. Оно помогает пользователю выбрать:

- продолжить ранее начатое обучение;
- пройти короткое обучение;
- пройти полное обучение;
- отложить обучение;
- отключить показ этого окна при запуске.

Технически это безопасная фронтенд-доработка:

- данные хранятся только в `localStorage`;
- сервер, API, базы, принтеры и проекты не изменяются;
- используются ключи `farm_tour_progress_v1`, `farm_tour_completed_v1`, `farm_tour_start_prompt_v1`;
- если обучение завершено кнопкой «Готово», окно больше не показывается автоматически;
- если обучение закрыто на середине, окно предлагает продолжить.

Проверка после правок:

```bash
node --check web/app.js
node --check web/composables/tourSteps.js
node --check web/tour/validate-tour.mjs
node web/tour/validate-tour.mjs
```

Ручная проверка в браузере:

1. Открыть приложение в новом браузере или очистить ключи `farm_tour_*` в `localStorage`.
2. Убедиться, что появляется окно выбора обучения.
3. Запустить короткий тур.
4. Закрыть тур на середине — в настройках и стартовом окне должно быть «Продолжить обучение».
5. Завершить тур кнопкой «Готово» — прогресс должен очиститься, а автоматическое окно не должно появляться снова.
6. Отметить «Не показывать это окно при запуске» — ключ `farm_tour_start_prompt_v1` должен стать `0`.

## Этап 10 — демо-сцена проекта и подсчёта деталей

Добавлена безопасная демонстрационная панель для раздела `Проекты и производство`.

Что показывает панель:

- пример производственного проекта;
- импортированный файл `gcode.3mf`;
- найденные `Label Objects`;
- строки деталей с колонками `На плате`, `Нужно`, `Напечат.`, `Статус`, `Файл`;
- пример, как после успешной печати файла увеличивается счётчик `Напечат.`;
- предупреждение, что без меток объектов приложение не должно угадывать количество.

Технически это безопасная фронтенд-доработка:

- панель рендерится только во время шага тура с `scene: 'project'`;
- панель не вызывает API;
- панель не пишет в базу;
- панель не создаёт и не меняет реальные проекты;
- панель не влияет на подсчёт деталей и логику печати.

Связанные файлы:

```text
web/app.js
web/index.html
web/app.css
web/composables/tourSteps.js
web/tour/validate-tour.mjs
web/tour/TOUR_GUIDE_RU.md
```

При добавлении новых элементов в эту демо-панель нужно:

1. добавить новый `id` или `data-tour` в `web/index.html`;
2. использовать этот селектор в `web/composables/tourSteps.js`;
3. если добавляется новая `scene`, добавить её в `web/tour/validate-tour.mjs`;
4. если добавляются новые тексты шага или подсказки, добавить русский перевод в `web/app.js`;
5. запустить `node web/tour/validate-tour.mjs`.


## Ревизия текстов обучения — этап 17

На этом этапе тексты тура приведены к единой терминологии для оператора фермы.

Рекомендуемые термины:

| Термин | Как использовать |
|---|---|
| файл печати | готовый g-code / 3MF, который можно отправить на принтер |
| модель | STL / STEP или другой файл, который ещё нужно нарезать |
| плита | набор деталей внутри одного файла печати |
| На плате | сколько конкретной детали печатается одним файлом |
| Нужно | требуемое количество деталей |
| Напечат. | принятое готовое количество |
| перепечатка | повторная печать детали после брака / rework |
| Quick Tasks | название раздела, не переводить в тексте интерфейса |

Правило для новых текстов: основной `text` должен быть коротким и понятным без раскрытия блока «Подробнее». Подробности добавлять в `more`, если без них карточка становится слишком длинной.
