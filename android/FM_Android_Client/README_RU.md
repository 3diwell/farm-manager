## Android 0.12: сохранение входа до 8 часов

Предыдущий APK: **`dist/FM-Client-0.12.0-debug.apk`**, сохранён отдельно.
На экране подключения включите «Запомнить вход на 8 часов» и выполните обычный вход.
Следующие запуски проверяют сохранённый сеанс у FM и открывают склад без ввода пароля.
Срок отсчитывается от входа, не продлевается при запуске и может закончиться раньше после
перезапуска FM или отзыва доступа. При временной потере связи доступен повтор подключения.
«Выйти» удаляет сохранённый вход, в том числе без сети. Пароль не сохраняется.
Сеанс зашифрован AES-GCM; ключ находится в Android Keystore, файл исключён из резервных копий.
Изменения ядра и серверного модуля не нужны. Приветственный экран отключается прежним
переключателем в настройках приложения; проверка входа выполняется параллельно заставке.
Установка, проверки и ограничения: `UPDATE_0.12.0_RU.md`.

## Актуальный модуль ПК: склад 1.7.31 — версия Claude + цены партий

Файл обновления склада: `dist/3diwell-module-inventory-1.7.31.zip`.
Основа — присланный модуль Claude 1.7.30. Сохранены его исправление списания
с внешней катушки AD5M, английские единицы и отдельный контракт совместимости.

Без цены всё работает как раньше; старые партии и принятые катушки не переоцениваются.

ревизии: mobile `0.8.0-pricing`,
desktop labels `0.6.0-prepared-prices`. Это не номер версии Android.
Нужно обновлённое ядро Claude с поддержкой `core_contract`: его установщик,
загрузчик, все 31 маршрута и отображение версии проверены изолированно.
В рабочий FM модуль автоматически не устанавливался.

Сборка только этого пакета: `python server/build_merged_module.py`.

Предыдущий `inventory-1.7.29-desktop-prices-0.8.0.zip` оставлен для истории:

## Возможности прототипа

1. Вход в локальный FM по HTTP/HTTPS с существующим пользователем.
2. Нативная камера Android: QR и штрихкоды, выбор при нескольких кодах в кадре.
3. Ввод кода вручную; OCR латиницы с обязательной проверкой текста.
4. Выбор места хранения, приёмка одной новой полной катушки, привязка к существующему
   материалу или создание нового. Неизвестный код оператор один раз связывает с товаром.
5. Раздельные общие коды товаров и уникальные коды отдельных катушек.
6. Сканирование позиции принтера и катушки, подтверждённая безопасная привязка.
7. Собственные QR катушек и позиций; печать через Android или сохранение PDF.
8. Повтор одного запроса после обрыва без дубля складского прихода.
9. Снятие катушки: по QR позиции, коду катушки или выбором из списка установленных.
10. Подтверждённая замена в занятой позиции: старая катушка отвязывается, новая привязывается
    одной операцией. Остатки, прежнее место хранения и существующая история сохраняются.
    В журнал добавляются перемещения с нулевым расходом. Само сканирование ничего не меняет.
11. Оформление в палитре FM: тёмная/светлая тема, крупные кнопки с линейными иконками,
    нижняя навигация, поиск катушек, сокращённая форма для существующего материала.
12. Сохраняемые на телефоне партии приёмки. QR всех подтверждённых катушек партии —
    одним PDF; повторный запрос не добавляет вторую этикетку.
13. Выбор нескольких ранее принятых катушек для общего PDF. A4, 8 этикеток на страницу,
    до 500 катушек в файле; векторный QR, подпись и индивидуальный ID.
14. Предварительные этикетки: материал, масса и количество → PDF с уникальными QR,
    пока без катушек/прихода. Затем приёмка по QR на выбранную полку.
15. Подготовленные партии хранятся в FM и доступны нескольким телефонам. Частичная приёмка,
    повторная печать, отмена одной или всех ожидающих меток; повторный скан не дублирует приход.

На штатном модуле без мобильного расширения разрешено только чтение. Клиент не отправляет
небезопасные запросы старого формата в обход проверки совместимости.

## Как проверять

Для предварительных этикеток нужны клиент И модуль 0.4: `UPDATE_0.4_RU.md`.
Ядро менять не требуется. Ранее добавленный дизайн и PDF обычных партий описаны в `UPDATE_0.3_RU.md`.
Обновление серверного модуля с версии 0.1 описано в `UPDATE_0.2_RU.md`.
Пользователь подтвердил приёмку, заполнение полей, создание QR и привязку в версии 0.1.
Снятие и замена 0.2 требуют отдельной проверки на телефоне; демосервер не обязателен.

Для изолированной пробы доступен встроенный демонстрационный сервер, БЕЗ установки модуля
в рабочий FM. Из папки проекта выполнить `python server/demo_server.py --host IP_КОМПЬЮТЕРА`.
В клиенте указать `http://IP_КОМПЬЮТЕРА:8011`, логин/пароль `demo` / `demo`.
Это только вымышленные полки, P2S и K2 Plus; база находится в памяти и исчезает при остановке.
Порт в интернет не открывать. Без `--host` сервер слушает только сам компьютер.
При первом запуске нужно разрешить Python доступ в частной сети в настройках Windows,
если межсетевой экран его блокирует. Рабочий FM на 8000 не затрагивается.
Для demo и HTTP-теста достаточно `fastapi` и `uvicorn`.

Порядок первой установки на отдельной тестовой FM:

1. Требуется Android 8.0 или новее. Передать APK на телефон и разрешить установку именно
   выбранному источнику на время установки. Это debug-сборка для теста, не публикация в магазине.
2. Сначала использовать отдельную тестовую установку FM 3.0 с копией данных/пустым складом.
   Самовольное копирование или переключение DATA_DIR работающей программы не допускается.
3. На тестовой установке сделать штатную резервную копию, затем установить тестовый ZIP
   через управление модулями. После перезапуска проверить, что обычный склад открывается.
   Если установщик не принимает пакет той же версии, НЕ обходить проверку удалением данных:
   нужна согласованная версия модуля и реестра ядра перед установкой.
4. Включить доступ FM по локальной сети штатными настройками и настроить пользователя
   с правом операций склада. Не отключать защиту ради подключения; не открывать порт в интернет.
5. Подключить телефон к той же доверенной сети. Ввести адрес компьютера, например
   `http://192.168.1.10:8000` (это пример, не адрес вашей установки). `localhost` на телефоне — сам телефон.
6. Пройти сценарии в `ACCEPTANCE.md`. Записи на настоящем складе — только после их успешной проверки.

## Честные ограничения первой версии

- OCR русского текста ещё не реализован: русский текст вводится вручную. Камера распознаёт
  коды независимо от языка подписи. Материал/цвет/масса не угадываются из произвольного QR.
- Обычная приёмка/установка требует подтверждения. Для подготовленной партии оператор
  заранее проверяет материал/массу, выбирает полку и явно включает приёмку по QR.
  После этого каждый скан сразу выполняет приход без отдельного подтверждения.
  Камера считывает по одной метке: после ответа FM нажмите «Сканировать следующую».
- Занятый слот заменяется только после сканирования новой катушки и подтверждения.
  Прямой перенос катушки с другого принтера запрещён: сначала явно снять её.
  Если другой оператор изменил привязку после открытия подтверждения, запрос отклоняется.
  Для новых операций нужны и модуль 0.2, и клиент 0.2; старые QR менять не нужно.
- Для привязки нужны свежие данные принтера и состояние простоя. Не подтверждённые позиции
  не угадываются. Некоторые модели могут потребовать уточнения названий состояний после теста.
- Общий EAN не различает одинаковые катушки — требуется выбор или собственный QR.
- Одиночная метка — через Android-печать/PDF; партия — напрямую в один PDF A4, по 8 меток.
  Форматы рулонных термоэтикеток пока не реализованы. История обычных приёмок хранится на телефоне,
  не синхронизируется с другими операторами и теряется при удалении данных приложения.
  Подготовленные партии 0.4, напротив, хранятся в базе склада FM.
  Ранее принятые катушки доступны через ручной выбор для экспорта.
- Нет печати заданий/управления принтером из клиента, фоновых складских операций и облачной базы кодов.
- Разрыв связи после отправки не означает отмену. Подключитесь к тому же серверу и нажмите
  «Проверить / повторить незавершённую операцию»; не очищайте данные приложения для повторной приёмки.
- При пересоздании экрана (например, повороте телефона) может потребоваться повторный вход/
  сканирование; отправленная операция остаётся сохранена. Пароль и cookie не сохраняются на диске.
- HTTP не шифрует пароль, cookie и складские данные. Только доверенная LAN; HTTPS поддерживается
  при штатно доверенном сертификате. Сертификатные ошибки не отключаются.
